# Planning records

This folder is a historical record. A spec here records how a decision was made at the
time, with the evidence and the rulings that settled it. Once the release it describes
ships, only its status line changes. For a shipped spec, where it and the code disagree,
the code is right.

Current truth lives elsewhere:

- `ROADMAP.md` for the release plan and what each release promises.
- `docs/` for how the library behaves.
- `CONTRIBUTING.md` for the rules a contributor follows, and `CLAUDE.md` for an agent.

Implementation plans and their task files are local working files under `planning/plans/`,
which is gitignored and never committed.
