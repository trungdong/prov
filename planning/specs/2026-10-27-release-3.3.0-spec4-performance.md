# Release 3.3.0, spec 4: performance

**Status:** Approved.

Written 2026-10-27 against `main` 98c339e (spec 3's PRs 17 to 24 and #686 merged; the
freeze not yet cut). Spec 1 is `2026-10-20-release-3.3.0-design.md`; its section 7.3 sets
the release-wide A/B and its target, and its amendment of 2026-10-22 resets that target.
Spec 3 is `2026-10-23-release-3.3.0-spec3-names-provn.md`; its sections 2 and 13.1 record
the costs 3.3.0 carries by design.

The labels T1.1 to T3.6 are those of a performance audit of `main`. A feasibility study
re-measured the audit's figures on a quiet machine (Apple M2 Max, CPython 3.12.8, rdflib
7.6.0, on mains power), and this spec carries every figure it relies on. Unless a sentence
says otherwise, a timing is `benchmarks/ab.py <ref> --python 3.12 --passes 6`, which
reports the median of per-pass minimums; an unchanged tree reads within about 2% of
itself.

## 1. Purpose

This spec takes the speed changes the study recommends for 3.3.0 into the release and
closes the reconciling measurement the maintainer asked for on `deserialize[json]`.

- **The writers** (section 3.1). The PROV-XML attribute order as one stable sort (T1.1),
  the PROV-O writer's attribute loop (T1.4's R1, corrected; R3 is dropped, S12), its
  per-bundle graph on rdflib's `SimpleMemory` store (T2.3), and the PROV-N lexer's
  `Token` unfrozen (T1.5).
- **The model** (section 3.2). The construction path (T1.2), `unified()` keyed by `id()`
  (T1.6, the id-keyed variant) and `add_namespace` in constant time (T1.7). The PROV-JSON
  reader's lookup shortcut (T1.3) is dropped (S8).
- **The release figure** (section 3.3). Where the freeze A/B is quoted and what it is
  called.

Every change in 3.1 and 3.2 leaves every output, error and warning as it is on `main`. An
output-identity check found no difference for any of them. It reads every fixture under
`src/prov/tests` with its reader, then writes the benchmark document, the `examples.py`
documents and every fixture document in each format, reads each back, and compares
`unified()`, `flattened()`, document equality and `prov_to_dot`, under `PYTHONHASHSEED` 1
and 2. The check misses two cases, a formal attribute holding several values and two
equal records sharing an identifier with a third, and the tests of section 5 pin both.

## 2. Evidence

### 2.1 Where `main` stands against 3.2.3

`ab.py 3.2.3`, run twice on `main`: `deserialize[json]` +18.5% and +19.7%,
`deserialize[jsonld]` +16% to +17%, `construct` +7%, `prov_to_graph` +44% (by design,
spec 3 section 13.1), and every other case flat or faster. With the changes of 3.1 and
3.2 applied together (and T1.3 and T1.4's R3, without T2.3), two runs give `deserialize[json]` +9.1%
and +9.3%, `prov_to_graph` +27% to +28%, `unified` −24% and `deserialize[provn]` −31%.
T1.3 measured at the noise floor, and S8 drops it.

### 2.2 The ten points since 2026-10-22

Spec 1's amendment of 2026-10-22 measured `deserialize[json]` at +12.9% against 3.2.3 after
PR 13 and put it at about +9% with that day's two fixes, which merged as #626 (536f0de).
The study measures `main` at +19%. This spec isolates the difference.

**Timing.** `ab.py 536f0de` on `main` 98c339e, twice: `deserialize[json]` +9.3% and
+9.0%, `deserialize[jsonld]` +17.9% and +17.4%, `construct` +12.1% and +10.8%,
`prov_to_graph` +47.8% and +47.7% (section 13.1 of spec 3, by design). The same A/B run
from a worktree at #631's merge against its first parent (`ab.py f0a802e`, that tree's
`ab.py`, which reports the minimum rather than the median of minimums) gives
`deserialize[json]` +6.2%, `construct` +6.7% and `unified` +8.4% for that one merge.

### 2.3 Three audit patches change output

The audit's T1.6 patch makes `unified()` keep an unmerged copy when two equal records
share an identifier with a third. Its return type, `dict[ProvRecord, ProvRecord]`,
collapses the equal records onto one key, so the second copy is never mapped. The audit's
T1.4 R1 iterates `formal_attributes + extra_attributes` and drops every value after the
first of a formal attribute that holds several, which the model allows when
`prov:collection` is added with them. The full suite passes on both, and the audit's
combined patches carry the T1.6 defect. Sections 3.1 and 3.2 specify the corrected forms,
which are the ones measured.

T1.4's R3 builds the qualification head once per relation. On `main`, an identified
relation rebuilds it for every attribute, and each rebuild removes the record type's
`rdf:type` triple when a `prov:type` is `prov:Revision`, `prov:Quotation` or
`prov:PrimarySource`. An asserted `prov:type prov:Derivation` adds that triple back in the
loop, so on `main` it survives only when that value comes last in `record.attributes`.
With R3 it always survives. A probe of 150 such derivations found the output differing in
106, and R1 alone identical in all 150. R3 is dropped (S12).

## 3. Design

No function that 3.1 or 3.2 changes exceeds Lizard CCN 14. Each plan's complexity ledger
records every function it changes, before and after.

### 3.1 The writers

**T1.1, PROV-XML attribute order** (`bundle.py`, `provxml.py`). `sorted_attributes`
becomes one stable sort on (rank, name text, value text), with the rank from a
module-level `_xml_attribute_rank` beside it, and `_infer_xsd_type` tests the prov-time
exception before formatting. The sort is exact, because a stable sort on that key gives
the old grouping, and the rank lookup matches names by `QualifiedName` equality as the
old `!=` did. Testing the prov-time exception first returns the same pair, because
`XSD_DATETIME` comes only from a `datetime`. `serialize[xml]` falls 18.2%, and one record
with 4,000 interleaved attributes goes from 0.217 s to 0.012 s, now linear.
`sorted_attributes` keeps its signature; it is public (`prov.model.sorted_attributes`)
and `dot.py` calls it too.

**T1.4, the PROV-O writer** (`provrdf.py`, S12). In `_encode_element` and
`_encode_relation`, R1 iterates `record.attributes` alone, which holds every non-`None`
formal value, and never `formal_attributes + extra_attributes`. R1 is exact, because the
dropped iterations carry either `None`, which both loops skip, or a value
`record.attributes` also holds, and the last attribute the loop visits is the same. The
per-attribute head rebuild and its `bnode` guard stay as they are on `main` (section 2.3).
`serialize[rdf]` fell 11.3% for R1 alone, measured under load; R1 with R3 fell 14.3%.

**T2.3, the per-bundle graph's store** (`provrdf.py`, S2). `encode_document` builds each
graph it passes to `encode_container` as `Graph(store="SimpleMemory", identifier=...)`,
with `prov` bound as `encode_container` binds it today, and passes it in as `container`.
`encode_container`'s own default stays `Graph(identifier=identifier)`, so a caller of the
public method gets the graph it gets today. The docstring sentence that says
`encode_document` always passes `None` changes to say what it passes. `SimpleMemory`
imports on rdflib 7.0.0, the pinned floor. Measured as a one-line change inside
`encode_container`, T2.3 took about a further 7.5% off `serialize[rdf]` beyond R1 and R3, with
identical output; the PR re-measures it in this form. No new signature.

**T1.5, the PROV-N lexer's `Token`** (`provn_lexer.py`). `@dataclass(frozen=True, slots=True)`
loses `frozen=True`. Nothing in `src/prov` assigns to, hashes or replaces a `Token`.
`deserialize[provn]` falls 13.5%.

### 3.2 The model

**T1.2, the construction path** (`records.py`). A1 tests `Identifier` first in
`_value_key`, which is exact because `Identifier` subclasses none of the types tested
before it. A2 scans for `prov:collection` only on the duplicate path of
`_store_attribute_value`, evaluating the same `any()` over the same pairs. A3 drops two
checks in `add_attributes` that never fire, because `mandatory_valid_qname` never returns
`None` and a `QualifiedName` is no `datetime`. The parameter that carries the pairs into
`_store_attribute_value` is named for its use, and the comment says it is scanned only
when a single-valued attribute repeats. `construct` falls 10.9%, `deserialize[json]`
6.3%, `unified` 7.0% and `prov_to_graph` 5.3%; A2 carries most of it.

```python
def _store_attribute_value(
    self, attr: QualifiedName, value: Any, pairs_for_collection_check: ...
) -> None: ...
```

The exact parameter name and type are the plan's; the signature is private.

**T1.6, `unified()` by `id()`** (`bundle.py`). `_unify_record_group` returns
`dict[int, ProvRecord]` and maps `id(record)` to the merge for every record of the group,
so equal copies each have an entry; `_unified_records` looks a record up with
`merged_records.get(id(record), record)`. Any record a merge replaces shares its
identifier and type, so it is in that group (section 2.3). `unified` falls 15.7% and
`prov_to_graph` 5.8%.

```python
def _unify_record_group(...) -> dict[int, ProvRecord]: ...
```

**T1.7, `add_namespace`** (`namespaces.py`). The membership test `namespace in
self.values()` becomes `self.get(namespace.prefix) == namespace`, with a two-line comment
saying every namespace is stored under its own prefix. The test is exact, because
`Namespace` equality is prefix and URI, and every write stores a namespace under its own
prefix. The benchmark is flat, as expected, and declaring 8,000 namespaces goes from
1.73 s to 0.010 s, now linear.

### 3.3 The release figure

The release PR (25) runs `ab.py 3.2.3 --python 3.12` on the freeze commit, as spec 1
section 7.3 sets, and quotes the result in `HISTORY.md`'s opening summary sentence, where
3.2.3 put its figure (S4). T1.1 and T1.7 get no Fixes line; if the quadratic removals are
mentioned, they are one clause of that sentence (S3). The sentence names the remaining
`deserialize[json]` cost by what section 2.2 attributes it to (S5, S10). No PR in this spec
adds a `HISTORY.md` entry.

## 5. Tests

The plan consolidates each test into the existing test it belongs beside; none is a new
module.

- **24a.** `sorted_attributes` order on same-IRI, different-prefix names and interleaved
  values (beside the PROV-XML writer's tests). The PROV-O writer keeps every value of a
  repeated formal attribute (`test_rdf.py`); it fails on the audit's R1. `encode_container`
  called without `container` returns a graph on rdflib's default store (`test_rdf.py`),
  pinning S2's boundary. T1.5 adds nothing; `test_provn_lexer.py`'s slots test holds.
- **24b.** `unified()` merges every copy of an equal record (`test_unification_rules.py`);
  it fails on the audit's T1.6. `add_namespace` returns the registered namespace for an
  equal one and still renames a clash (`test_namespaces.py`). T1.2 adds nothing; the
  suite covers its paths.
- **Every PR.** The output-identity check of section 1, under `PYTHONHASHSEED` 1 and 2,
  shows no difference from `main`. The plan carries the check, and its result goes in the
  plan's report, not in a commit.

## 6. Out of scope

- **T2.1, caching `_typed_attributes()` on the record** (S1). One issue carries the
  change, its guard test, the count of `prov_to_graph`'s hashes that networkx makes on
  node keys (65,200 of 86,450), which a per-operation cache never sees, and the unmeasured
  cost of keeping a frozenset and its tuples on every hashed record.
- **T2.2, the URI string in the value key.** After 3.3.0, with a non-optional helper in
  place of a `type: ignore`. It takes GC-tracked objects per record from 9.9 to 7.4.
- **T3.1 to T3.3.** Issues. Reading RDF that declares no prefixes is quadratic (T3.1), and
  so is `flattened()` on a document whose many bundles declare namespaces (T3.2); both
  were quadratic in 3.2.3. A "trusted copy" path for `flattened()` and `unified()` (T3.3)
  is a second construction path and high risk.
- **T3.6, the benchmark generator** (S6). The first PR after the release, with the GC note
  for `benchmarks/README.md` and one rerun of the 3.2.3 A/B, so 3.4.0 starts from the
  intended document; an issue until then. `ab.py` runs both sides from the working tree's
  `benchmarks/`, so the fix changes both sides' workload equally.
- **The growth of the shared `PROV` and `XSD` `Namespace._cache`** (S7). It grows linearly
  in the distinct names a process reads and is never trimmed. An issue.
- **A `dot.py` defect the audit found.** `dot.py` compares a record's `label` (a `str`)
  with an `Identifier`, which never matches, so every unlabelled node shows its identifier
  twice. An issue, outside this spec.
- **The audit's other `dot.py` report.** Not filed, because `prov_to_dot(bundle)` warning
  through `ProvBundle.unified()` is what spec 3 section 13.5 rules (N36).
- **The second resolution walk in the PROV-JSON reader** (`_check_name`, then
  `mandatory_valid_qname`). No spec 3 follow-up (S5), because the audit priced it at about
  3% of the read on a trusted entry point.
- **T1.4's R3, the qualification head built once** (S12). One issue, with the order
  dependence of `main`'s `rdf:type prov:Derivation` that section 2.3 describes, which R3
  would end as an output change.
- **Pickled `_resolve_cache` entries** (4.4% of a pickle, valid after unpickling) and the
  autovivified attribute entries (S11).
