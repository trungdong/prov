## 2. Evidence

Every issue was re-probed on `main` 79f29c2 (`/tmp/spec3/probe.py`, 2026-10-23). The
reproductions in the issues hold, with three findings that change what this spec proposes.

**#573's premise is wrong.** The PROV-N Recommendation, section 3.4.1, reads "Each
identifier occurring in a bundle, including the bundle identifier itself, MUST be
interpreted with respect to the namespace declarations of that bundle, or if the
identifier's prefix is not declared in the bundle, with respect to the namespace
declarations in the document." Its scoping example (section 3.7.4) reads `bundle e001`
under a bundle-level `default` as that default's IRI. XML namespaces give an element's
own `xmlns` declarations scope over its own attributes, so `prov:id` on `bundleContent`
follows the same rule, and a JSON-LD node's `@context` applies to its `@id`. The four
readers therefore resolve a bundle identifier correctly today, and
`test_bundle_identifier_resolves_against_its_own_prefix` pins it. The defect #573
reproduces is in the writers, which spell the identifier `ex:b2` inside a bundle that
rebinds `ex`, a form every reader must read as the bundle's IRI. The PROV-JSON and
PROV-JSONLD writers even carry the comment "a reader resolves the bundle identifier in the
bundle's own scope" and then write the misreading form. Section 4.4 fixes the writers;
the readers do not change (N1).

**The cost PR 16 added sits in resolution and the value store, not in the collapse.**

warm call then one profiled call):

and on read `decode_document` registers it as a namespace with an empty prefix, not as the

whether to file one.

## 3. The value table and the reader path

### 3.1 One table for collapse and equality (Q4)

**Rule, unchanged.** A typed literal collapses to a Python value at assertion when, and
only when, the value is one `prov` writes back with the same text and the same datatype:
the text is in the datatype's lexical space, the value's canonical datatype is the
asserted one (#235, so `"5" %% xsd:long` and `"5" %% xsd:short` stay literals), and the
text is the canonical spelling (E6, so `"05"` and `"1e0"` stay literals). The table in
section 2 is the pin; `test_literal_forms`, `test_writer_spells_booleans_as_words` and the
spelling table in `test_literal_semantics.py` already assert it.

**Mechanism.** `_convert_typed_literal(literal, datatype)` becomes three steps. An
`xsd:string` literal is its text. An `xsd:dateTime` literal goes through
`parse_xsd_datetime` as today, and stays a `Literal` when the text has no value or the
offset is beyond ±14:00 (#513, #514). Every other datatype goes through
`xsd_value(datatype, text)`; `None` keeps the `Literal`, and a value of one of the three
plain types with a value space here, `bool`, `int` or `float`, collapses when
`python_value_form(value) == (text, datatype)`, the one comparison that holds the #235
rule and the canonical-spelling rule at once (3.3 defines `python_value_form` for the
plain types). An `xsd:decimal` value is a `Decimal`, which the model never holds plain
(#482 stores it as a `Literal`), so it is excluded by name and keeps the `Literal` without
the `Decimal` round trip a bare comparison would take; `xsd:float` stays a `Literal`
because its form is `xsd:double`. The collapse therefore yields only `str`, `bool`, `int`,
`float` and `datetime`. The `try`/`except`, the separate #235 branch and the second
spelling comparison go, and `XSD_DATATYPE_PARSERS` is no longer read anywhere in the
package.

`_double_value` returns the `float`, `NaN` included, so `xsd_value(XSD_DOUBLE, "NaN")`
changes from the text `NaN` to a `float` NaN, the one row of its table that moves. The
substitution of `NAN_KEY` for a NaN moves into one helper, `_values.key_slot(value)`,
called by `Literal._key()` and `_value_key`, which today each spell the rule, so every key
is as before. `xsd_value` then means what its name says.

`XSD_DATATYPE_PARSERS`, `parse_xsd_types`, `SupportedXSDParsedTypes`, `DATATYPE_PARSERS`
and `parse_boolean` are in the frozen `dir(prov.model)` snapshot. They stay exported and
documented with no production caller (`parse_boolean`'s last one is the `XSD_BOOLEAN` row
of the dict this step stops reading), under the ruling of 2026-10-23 that a frozen public
helper is not removed for being unused; a 3.4.0 dead-helper sweep decides their fate.
`HISTORY.md`'s sentence that `XSD_DATATYPE_PARSERS` has no `xsd:anyURI` entry stays true;
the comment at `provrdf.py:109` that calls `LITERAL_XSDTYPE_MAP` its reverse map is
reworded.

**Q6.** `Literal(Decimal("NaN"), XSD_DECIMAL)` stays as it is (N3). A `Literal` holds the
text its caller gave it, however it was spelled: `Literal("NaN", XSD_DECIMAL)` and
`Literal(Decimal("NaN"), XSD_DECIMAL)` are one literal, an ill-formed text that compares
as text and writes back as written (C11 covers the one writer that cannot). The plain
path raises because a plain Python value must have a PROV form `prov` chooses; a `Literal`
is the caller choosing the form. The `Literal` docstring gains that sentence.

Ledger expectation, from the PR 16 review: about 13 fewer lines in `records.py`;
`_convert_typed_literal` CCN 9 to about 5. The speed effect is within the A/B's noise
(section 2); the A/B runs because `_values.py` and `records.py` are on every path.

### 3.3 One spelling for the writers

`_values.python_value_form(value)` (PR 9) returns `(text, datatype)` for a `Decimal`, a
`date`, a `time`, a `timedelta`, a `UUID` and the bytes-likes. It gains the five plain
types: `str` as `(value, XSD_STRING)`, `bool` as `true` or `false` with `XSD_BOOLEAN`,
`int` as its digits (`int.__repr__`) with `canonical_xsd_datatype(value)`, `float` as
`_xsd_double_text(value)` with `XSD_DOUBLE`, `datetime` as `_xsd_datetime_text(value)`
with `XSD_DATETIME`. Then one function says how `prov` spells a Python value, and the
places that spell one today call it: `encoding_provn_value` (CCN 8), the PROV-JSON
`encode_json_representation` (6), `encode_jsonld_value` (11), PROV-XML's `_infer_xsd_type`
(8) with the `v.lower()` in `_encode_attribute_value`, PROV-O's `encode_rdf_representation`
(8), `_literal_text` (8, which keeps its `float`-as-`xsd:decimal` case), and the collapse
test of 3.1. Each writer keeps its own wrapping (quotes, `{"$": ..., "type": ...}`,
`xsi:type`, an `rdflib.Literal`) and loses its type chain. `_xsd_double_text`,
`_xsd_datetime_text` and `canonical_xsd_datatype` with its two bounds move to
`_values.py`, where `python_value_form` lives and which imports nothing from `records.py`;
`records.py` and `prov.model` re-export `canonical_xsd_datatype` at its public location
(spec 2's "stays where it is" is amended at the top of this spec). The form table is an
ordered `isinstance` ladder, so `bool` precedes `int` and `datetime` precedes `date`. This
was code-review finding 7 and simplify item A2 of the PR 16 trial, deferred here.

### 3.4 The reader path

**One lookup for the readers (profiling candidate 1, #450 item 2).** Spec 1's D3 rule says
a reader resolves a name by splitting at the first `:` and looking the prefix up in the
declarations in scope, never by compacting an IRI. Today each reader does that twice per
name: `_check_name` or `_resolve` walks the scopes to learn the prefix is declared
(`unresolved_name_detail`, `_unresolved_reason`, `_prefix_in_scope`), then
`mandatory_valid_qname` walks them again through `valid_qualified_name`, which also tries
the cache, the `Identifier` branch and IRI compaction the reader never wants. A new
`NamespaceManager.lookup(prefix, local)` does the reader's resolution in one walk: the
nearest scope that binds `prefix` (or holds it in `_prefix_renamed_map`) mints the name
from that namespace; for an empty prefix, the nearest default namespace. It returns
`None` when no scope binds the prefix, and the caller then asks `_unresolved_reason` for
the sentence and raises its own positioned error. Two corners keep today's answers. The
pair `("", "")` returns `None` (an empty name, which `_unresolved_reason` reports as "it is
empty"), and the prefix `_` returns `None` whether or not a document declares it, as
`_resolve_string` refuses a blank-node label today. `ProvBundle` exposes it as
`_lookup(prefix, local)`.

The PROV-N parser's `_resolve`, `_resolve_escaped_colon`, `_identifier_text`,
`_check_name_value` and `_literal` call it with the pair the lexer already split, so the
escaped-colon shape needs no special path (a bare local part `a:b` is the pair
`("", "a:b")`) and `_literal` becomes "the name, or a `Literal`" as #450 asks. The
PROV-JSON reader's `_check_name` and `_decode_name` call it with the split text, so the
check-then-resolve pairs at record keys, bundle keys, attribute names, formal values,
members and value objects become one call each. PROV-JSONLD's `_decode_context` and the
model's `unresolved_name_detail` keep `_unresolved_reason` for the error path.
`valid_qualified_name` and `_resolve_prefixed_string` keep their shape for code, which may
compact (D3's last sentence). The expected gain is the 8% of the JSON read that the check
costs and part of the resolution share, measured by the A/B.

**The PROV-XML reader's namespace per name (candidate 4).** `xml_qname_to_QualifiedName`
builds a new `Namespace` for every non-PROV, non-XSD prefix it meets (22,500 per 10k-record
read), so `Namespace.__getitem__`'s cache never hits and `QualifiedName.__init__` runs for
every name. A per-deserialize map from `(prefix, uri)` to one `Namespace`, held on the
serializer instance for the length of `deserialize`, removes both. Behaviour-free, and
worth about 10% of the XML read.

**Deferred, with the reason.** The wrapper depth from `mandatory_valid_qname` to
`_reconcile_qualified_name` (candidate 5) is an API question, because
`ProvBundle.valid_qualified_name` is public and overridable; the lookup above removes the
reader's share of it. `unified()` re-coercing merged attributes (candidate 6) is a model
change for a case the benchmark barely exercises. Both wait for a measurement after this
spec's PRs.

## 4. Names and namespaces

### 4.1 Parent-aware reconciliation (#449)

`NamespaceManager._reconcile_qualified_name` never consults `self.parent`. A bundle handed
a `QualifiedName` the document owns copies the document's prefix declaration onto itself,
or adopts the document's default as its own when it has none, so declarations accrete
across round trips and the PROV-N parser works around it with a resolve-then-discard text
path (`_identifier_text`), a two-path bundle constructor (`_bundle`) and a test that pins
the escaped-colon shape as an accepted limitation.

**Rule.** A qualified name whose namespace an enclosing scope already binds, under the
same prefix and IRI, or as the same default, is returned as that scope's name (the name
itself when its namespace is that scope's object, else minted from that scope's namespace,
so a foreign `Namespace` object does not survive) and registers nothing on the inner
scope, unless the inner scope itself binds that prefix to another IRI, in which case
today's copy-and-rename applies. The walk is `_prefix_in_scope`'s, returning the binding
namespace rather than a flag. Spec 1's 5.8 rule made the string side consistent already
(`_resolve_prefixed_string` returns `None` when an enclosing scope declares the prefix, so
`valid_qualified_name` delegates); this is the `QualifiedName` side of the same rule.

**No inferred default (ruled 2026-10-24).** A default namespace is an explicit declaration,
and the model never sets one from a name it is handed. A name in a prefix-less namespace is
the scope's name when a default in reach declares the same IRI, and is otherwise rejected
with `ProvExceptionInvalidQualifiedName`, whose detail names the IRI and says to declare a
prefix for it (amended 2026-10-24 from "takes a declared prefix or `dn`"; the model mints no
prefix of its own, see 4.3). The 2014 branch that made a prefix-less name the scope's default when the scope
had none goes, with `_set_default`'s `register` parameter; the default is always the
namespace registered under `""`, which is what every scope walk reads. The one namespace the
model still registers of its own accord, the copy of a prefixed namespace an enclosing scope
binds to another IRI, takes a prefix no scope in reach binds, so the model never creates a
shadow. Nor may a declaration create one after the fact: `set_default_namespace` and
`add_namespace` on a scope that already holds a name whose IRI the new binding would change
(a bare name under the old default, a name under the prefix being rebound, the bundle's own
identifier included) raise `ProvException` naming the name, so the use-then-bind shape of
the next paragraph cannot arise and 4.4's N18 is superseded (amended 2026-10-24). Every place `prov` copies records into a scope it builds, `flattened()`,
`unified()` on a bundle and on a document, `add_bundle` given a document, copies the source
scope's default and declarations before the records (`ProvBundle.unified()`, whose copy belongs to no document, first declares the document's prefixes the bundle does not rebind, then the bundle's own, and takes the document's default when the bundle has none, so an IRI both scopes bind keeps the document's prefix; N26), and `add_bundle` given a bundle that already belongs to another document refuses it, because moving a bundle or individual records between documents is not a supported operation: provenance is an audit record whose manipulation stays within the data model's constraints (ruled 2026-10-24). A merge of scopes inside one document, `flattened()`, is a genuine conflict of a valid document, and minting a prefix there is acceptable, as `add_namespace` renames a clashing prefix. The prefix-less rule of `_reconcile_qualified_name` has three outcomes, not two: a default in reach declares the IRI, the default's name; else a prefix declared in reach is bound to the IRI and the asking scope resolves that prefix to it, that prefixed name; else the rejection. A target that
declares no default for a record's default-namespace name rejects the record with the
sentence above, where 3.2.x made that namespace the target's default; `HISTORY.md` lists it
under "Rejected input" (amended 2026-10-24).
The PROV-XML reader registers `xmlns` on `prov:document` as the document's default and
`xmlns` on `prov:bundleContent` as the bundle's (the reader half of #572); an `xmlns` on any
other element has no model scope, so a bare name under it raises `ProvXMLException` naming
the element and the IRI (the `nested_default_namespace.xml` fixture becomes a rejection
row; amended 2026-10-24).

**Only the API sets a default (ruled 2026-10-24).** A prefix-less `Namespace` is the model's
representation of a scope's default declaration and exists in no other role, so it cannot be
built by object construction: `Namespace("", uri)` raises `ValueError` naming
`set_default_namespace()`, which builds the object through a private constructor, and
`add_namespace` refuses a prefix-less namespace with the same sentence. A default namespace
object reaches another scope only through a record copied from the scope that declared it,
which is the case the previous paragraph's prefix rule covers. The readers that meet a
default declaration call `set_default_namespace` (PROV-N, PROV-JSON and PROV-JSONLD do
already); the PROV-XML reader resolves a bare name through the scope whose `xmlns` it
registered, and gives a name under an inner element's `xmlns` a prefix bound to that IRI;
the PROV-O reader registers the `""` binding through `set_default_namespace`, which is the
second bullet of 6.3 brought forward from PR 21, so a default namespace reads back through
PROV-O as the default from PR 18 (amended 2026-10-25: #473 is a rejection under N22 and has
no `rdf` row). `HISTORY.md` lists the constructor under "Rejected input".

**Use then bind.** The rule leaves one shape unprotected that the copy protected. A bundle
that asserts the document's `ex:e` and then calls `add_namespace("ex", other)` holds a
name whose spelling `ex:e` the bundle's own scope now reads as another IRI; today the copy
made the later binding rename itself to `ex_1`. The PROV-N, PROV-JSON and PROV-JSONLD
readers never produce this (they bind before they use), only code that declares after
asserting; the PROV-XML reader does, from an `xmlns:ex` redeclared on an element inside
`bundleContent`, and the no-shadow prefix rule above gives that binding `ex_1` as the copy
did (amended 2026-10-24). Section 4.4's writer rule
covers it (N18): a writer spells every name of a bundle with a prefix the bundle's scope
reads back, so the held `ex:e` is written under a prefix bound to the document's IRI, as
the bundle identifier is. `ProvDocument.unified()` builds each bundle's copy inside the new
document, which has the declarations already; `ProvBundle.unified()` builds a copy that
belongs to no document and declares what the bundle read through its document (N26, below).

**Consequences.** `_identifier_text` goes (the parser passes the resolved name;
`new_record` reconciles it and leaves it alone); `_bundle` has one path (build the bundle,
apply its declarations, resolve its identifier in its own scope, `add_bundle`), which is
also where #450 item 2 lands (section 3.4);
`test_bare_escaped_colon_name_in_bundle_adopts_the_enclosing_default` inverts to assert the
bundle gains no default; `test_bundle_with_own_prefixes`'s "ex is not copied" assertion
holds for the JSON reader too. Emitted declarations change for existing documents, because a
bundle now declares only what it binds itself, and `bundle.get_registered_namespaces()`
shrinks for user code. A bundle taken from a document and written alone with
`bundle.get_provn()` names `ex:e` with no declaration, so the text reads only inside its
document; no use case asks for more (N25). `HISTORY.md` lists the two under "Output
changes" (N15). PROV-JSONLD already writes an empty `@context` for a
bundle and PROV-XML declares every namespace on the root, so the bytes change in PROV-N and
PROV-JSON only. `ProvBundle.__eq__` compares records, not namespaces, so the
written-by-3.2.3 fixtures read equal.

### 4.2 A datatype's namespace registers at assertion (#615)

A `QualifiedName` used as an identifier, an attribute name or a value registers its
namespace on the bundle; a `Literal`'s datatype does not, and the PROV-N, PROV-JSON,
PROV-JSONLD and PROV-XML writers then write a datatype no declaration covers. The fix sits
where a kept `Literal` leaves `_convert_typed_literal` and where a `Literal` is stored
with no conversion: `_coerce_attribute_value` passes a stored `Literal`'s datatype through
`self._bundle.valid_qualified_name(datatype)` and, when the reconciled name is an unequal
name (a renamed prefix), rebuilds the `Literal` with it, so `get_attribute()` returns the
rebuilt one in that case. A datatype in a prefix-less namespace follows 4.1's rule: it is the
default's name when a default in reach is that namespace, else the literal is rejected with
the same sentence; it never sets a default (amended 2026-10-24). A language-tagged literal's
datatype is `prov:InternationalizedString`, in a default namespace, and costs nothing. The
readers already resolve a datatype through the bundle, so this is for code-asserted
literals; the five-format round trip of the issue's document joins `test_qnames.py`.

### 4.3 An identifier equal to a namespace IRI (#473, D12)

**Amended 2026-10-24 (N4 reversed).** A name in the default namespace with an empty local
part has no spelling, and the model mints no prefix for it: `d.entity("http://example.org/")`
under that default, and `d.entity(d.get_default_namespace()[""])`, raise
`ProvExceptionInvalidQualifiedName` with the detail "the IRI http://example.org/ is the
default namespace and has no qualified-name form; declare a prefix for it". A prefixed empty
local part (`ex:`, production [52]) stays legal and round-trips as today. #473 closes as a
rejection with that message; the conformance page's PROV-XML line about `prov:id="dn:"` and
the `dn:` HISTORY bullet go. The text below records the superseded design.

A record whose identifier is a namespace IRI has a `QualifiedName` with an empty local
part. With a prefix it is `ex:`, which PROV-N writes and reads, and the round trip holds
today. In the default namespace it has no PROV-N spelling, and the explicit `continue` in
`_resolve_prefixed_string` makes `d.entity("http://example.org/")` fail with the wrong
error, while the `QualifiedName` form is accepted and fails at write time.

**Rule (N4, recommendation).** The model gives such a name a prefix at assertion, in
`_reconcile_qualified_name`: a name in the default namespace with an empty local part is
rebuilt in a prefixed namespace bound to the same IRI, the registered one if there is one,
else `dn` (or `dn_1`, ...) registered then, the prefix `_reconcile_qualified_name` already
mints for a second default namespace. The same rebuild closes the compaction branch of
`_resolve_prefixed_string`, which is where a plain string arrives. The `continue` goes, `d.entity("http://example.org/")`
returns `<QualifiedName: dn:>` under a default namespace, every writer writes `dn:` with
its declaration, and `provn_bare_representation`'s raise stays as the guard for a bare
`QualifiedName` printed outside a document. One site, no writer change, and the rule is
the one the model already applies to a name in a foreign default namespace.

Two formats need a sentence each. PROV-O's reader registers the writer's `@prefix :`
binding as a namespace with an empty prefix (section 2), so `ex[""]` fails to read back
through RDF today and `dn` would never be minted on that path; the fix is 6.3's and PR 21
carries the RDF row of the round trip. PROV-XML's `prov:id` is an `xs:QName`, whose local
part is a non-empty NCName, so `prov:id="dn:"` is schema-invalid, as `prov:id="ex:"` is
today; `prov`'s reader reads both, other PROV-XML consumers may not. D12 asked for a form
every writer can express, and PROV-XML has none. N4 therefore carries a second half, to write
`dn:` and record the limitation on the conformance page's PROV-XML section (recommended,
because the same shape already ships for a prefixed name and a reader of `prov`'s output
gets the IRI back), or raise `ProvXMLException` for an empty local part.

The alternative is a write-time rule in each writer: `_provn_header_id` generalised to
records, `_JSONPrefixMap.qname_text` gaining `or not localpart`, and a pre-scan in
PROV-XML. It keeps `get_registered_namespaces()` free of `dn` until a write, at the cost
of three sites and a scan. Section 4.4 needs the write-time machinery for other defects,
so the alternative is not unreasonable; the recommendation stays with the model because
one rule in one place is what #473's "whether an IRI is a legal identifier depends on how
its namespace was declared" asks for.

### 4.6 The PROV-JSONLD node reference (#609, E11)

E11 (2026-10-22): a PROV-JSONLD node reference is a qualified name, and the reader rejects
one no namespace resolves instead of keeping an `xsd:anyURI` `Literal`. `decode_jsonld_value`
lines 503 and 504 serve both `{"@id": ...}` and a bare string under `type`, `role` and

is third-party input only.

A blank-node reference, `{"@id": "_:b1"}` or the bare `"_:b1"` under `type`, `role` or

refuses it, and 13.6 makes it no `PN_PREFIX`. On `main` (3f0863e) it reads as
`Literal("_:b1", xsd:anyURI)`, and the 5.8 sentence would tell the reader to declare `_`.
It follows N6's rule for a PROV-O blank-node attribute object that names no record (a
PROV-JSONLD blank node never names one, since a record with a blank `@id` is refused): the
value is dropped with one `ProvWarning` naming the record and the attribute, emitted by the
serializer (N48, ruled 2026-10-25).

The sentences that say "stored as an `xsd:anyURI` `Literal`" are
rewritten: `HISTORY.md` lines 76 to 79, the how-to's qualified-names section (lines 198 to
203), the conformance page's PROV-JSONLD bullet (lines 189 to 193), and `provjsonld.md`'s

node reference it read an `Identifier` silently, so the bullet goes under "Changes with no
prior warning" and says which half was warned.

**#610 (declined 2026-10-24, N31).** `ID_TYPED_TERMS` is the hand-written set `{"type", "role",
"location"}`, which the writer (`encode_jsonld_value`) and the reader (`decode_jsonld_value`)
consult to tell a bare qualified-name string from a node reference or a text. The vendored

### 5.1 Reader and writer refactors (#450) and the lexer and parser speed items

Four behaviour-free changes from the 3.2.0 taste review, plus two from the profiling pass,

1. **One table for `PN_LOCAL` escaping.** `provn_lexer.py` re-types `PN_CHARS_OTHER` and

### 5.2 Extensibility expressions (#520)

PROV-N section 5: compliant parsers MUST parse an `extensibilityExpression`, and compliant
implementations MAY ignore it. `_classify` raises on any prefixed keyword, and the lexer
has no `{` or `}`.

**Rule (N7).** A statement whose keyword is a `QUALIFIED_NAME` with a non-empty prefix,
other than `prov:mentionOf`, is an extensibility expression. The parser consumes it by the
grammar (an optional identifier, one or more arguments, each an identifier or marker, a
literal, a time, a nested expression or a tuple in `{}` or `()`, then an optional
attribute block) and drops it with one `ProvWarning` naming the predicate and its position,
under every profile; a syntax error inside it is a `ProvNSyntaxError` at the token as for
any statement, skipped under `lenient`. The lexer gains `LBRACE` and `RBRACE`, so a stray
`{` is a parse error at the statement rather than a lexer error, which `lenient` skips
where every profile raised before (D1; one clause in the HISTORY bullet). The parser checks
the expression's syntax only: no name inside it is resolved, its keyword included, so a
prefix declared nowhere inside a dropped expression is not an error, and the warning names
the keyword as written (N52, ruled 2026-10-25). Nesting is capped at 32 levels, after
which the parser raises "extensibility expression nested more than 32 levels" at the
offending token, so untrusted input cannot recurse the parser out of its stack. Every
bracket an argument opens counts as a level, a nested expression's `(` and a tuple's `{`
or `(` alike, because the grammar nests tuples inside tuples as well as expressions (N53,
ruled 2026-10-25). An
unprefixed unknown keyword stays "unknown statement keyword", a bare `mentionOf` under
`strict` keeps its hint, and `prov:mentionOf` keeps its interpretation.

The warnings are emitted by the serializer, not the parser, through the `skipped` list as
the lenient skips are, so `prov.read()` attributes them to its caller. The corpus:
`prov-n-example-63` and `prov-n-example-64` leave the Recommendation exclusions, and
`prov-family` and `prov-family-graphics` leave the ProvToolbox exclusions (their
`prov:derivedByInsertionFrom(...)` is a prefixed expression; both parse clean with it
stripped, 742 and 764 records). `container1` stays excluded with a new reason: its
`bundle ex3:b2` uses a prefix declared nowhere, which raises under every profile, and it
holds `wasRevisionOf`, `wasQuotedFrom` and `hadPrimarySource` statements, which PROV-N has
no production for. A third table in `test_provn_corpus.py`, `IGNORED_EXTENSIONS`, maps the
four files to the number of expressions dropped (one `dictExt:hadMembers` in each example,
twelve `prov:derivedByInsertionFrom` in each family file, counted at 3f0863e), and its guard test asserts that many
`ProvWarning`s, since PR 13 turned `ProvWarning` into an error for the corpus tests. The
conformance page's "Corpus evidence" rows change to 94 parse and 33 excluded, and 6 parse
and 3 excluded; the corpus README loses the "unsupported by design" wording for the four
and rewords `container1`. The PROV-N profiles table in `provn.md` replaces its lenient-row
sentence "Extensibility expressions (`prefix:name(...)`) are skipped this way" (they raise
today and parse under every profile after this), the conformance page's profiles note that
the set-of-pairs literal is not supported goes, and `ProvNParser`'s docstring names the
warning. This PR touches the reader's input path, so the review regime runs the
bug-and-security subagent on it.

### 5.3 Wrapped output (#131)

The writer puts every statement on one line. The Recommendation's examples break a long
statement before its attribute block and align the pairs:

```
wasDerivedFrom(ex:d; e2, e1, a, g2, u1,
               [prov:type='prov:Revision',
                ex:comment="a righteous derivation"])
```

**Rule (N2, recommendation (a)).** A statement whose one-line form, indentation included,
fits in 80 columns is written on one line. Otherwise the keyword, identifier and formal
arguments stay on the first line and the attribute block starts on the next, indented to
the column after the opening parenthesis, one pair per line, each after the first indented
one column further, under the first pair. The formal list and a single long value are
never broken. `ProvBundle.get_provn` and `ProvRecord.get_provn` gain `width: int | None =
80`, and `serialize(format="provn", width=...)` passes it through; `None` never wraps, for
output that is grepped line by line, and `ProvRecord.__str__` passes it, so `print(record)`,
log lines and assertion diffs stay one line. A subclass that overrides `get_provn(self,
strict=False)` fails when the bundle passes `width`; `HISTORY.md`'s "Project" heading says
so, as #491's override sentence did. Downstream golden-file comparisons of PROV-N bytes
break once, and the "Output changes" bullet names `width=None` as the old shape. The
default is the maintainer's call: `80` gives readable output to everyone and breaks the
golden files; `None` with `80` as an opt-in breaks nothing and leaves #131 reachable but
off. Alternative (b) puts the attribute block on its own line whenever there is one, with
no number to choose and no keyword, at the cost of every documented example with
attributes changing shape.

`README.md`'s example has no attribute block and no line over 80 columns, so it is
unchanged under either rule and stays in the list because it sits outside `docs/`; the
tutorial has five statements with attribute blocks, one over 80 columns (the entity with
four attributes), so (a) wraps one and (b) wraps five; `unification-flattening.md` has

## 6. PROV-O

### 6.1 A blank node behind an attribute predicate (#639)

`_decode_attribute_triple` passes the object through `decode_rdf_representation`, whose
"simple type" branch returns a `BNode` unchanged; `_emit_decoded_records` then hands the
label to `new_record`, which raises an invalid qualified name naming rdflib's label. A
blank node as the object of `prov:hadGeneration` or `prov:hadUsage` names a record that,
since E8, reads anonymous, so nothing in the document can be pointed at; PROV-N has no
form for the link.

**Rule (N6).** A `BNode` object of an attribute predicate follows E8's rule for the node
it names. One that is the subject of an element in the graph (a blank `prov:Plan` behind
`prov:hadPlan`, a blank entity behind `prov:entity`) resolves as that element's identifier,
the label in the default namespace that E8 gives the element, which today raises on the
label instead. One that is the subject of no element, a relation E8 made anonymous or a
node typed nothing, is dropped with one `ProvWarning` naming the subject and the predicate,
both compacted through the parse graph's bindings ("ex:e2: prov:hadGeneration points at a
blank node that names no record; the attribute is dropped"); a subject E8 made anonymous is
named by its type ("an anonymous prov:Derivation") (amended 2026-10-23). The derivation
reads without its `prov:generation`. The check sits in
`_decode_attribute_triple` after its exclusion of the `qualified*` and `asInBundle`
predicates, whose blank objects are the qualification nodes `prov`'s own output carries and
which that exclusion already drops silently, so it applies to the formal and extra-attribute
paths only. An extra attribute whose object was a blank node read as the label string
before and follows the same rule now; the HISTORY Fixes bullet says so. The conformance
page's PROV-O section gains the line, beside the one for a blank-node relation subject.
The test is the reviewer's Turtle case from spec 2, with a `hadPlan` row, and rides the
first PR with the fix (section 3.2), a few lines of code and two rows rather than an xfail
that a later PR inverts.

### 6.2 `xsd:duration` on read (#620)

The reader cannot keep the text rdflib has already rewritten, the same fact as C10's
fraction truncation, exponent decimals and numeric spellings. Caveat C9 folds into C10 as
one more item, the zero-duration row of `test_value_forms.py` keeps its known-lossy `rdf`
marking with the caveat as the reason, the how-to's sentence links C10, and #620 closes at
the release as documented (N9). No code changes.

### 6.3 rdflib's default bindings (new)

`decode_document` registers every binding of the parsed graph (line 1350), and rdflib's
namespace manager binds 29 by default, so a document read from any RDF syntax carries
them, and it registers the `""` binding as a namespace with an empty prefix instead of the
default (section 2). Four changes, in PR 21:

- The loop skips a `(prefix, IRI)` pair that a fresh `rdflib.Graph()` binds, computed once
  per `deserialize`, so a document that binds `dc` to another IRI keeps that IRI and only
  an unused prefix at rdflib's default IRI is lost. rdflib 7.6 renames the source's `dc` to
  `dc1` at parse, because its own `dc` is bound first, so the IRI reads under `dc1`, as it
  does on `main` (ed0c9b8). (The `""` binding is registered through
  `set_default_namespace` by PR 18, section 4.1 "Only the API sets a default", amended
  2026-10-24.)
- The relation path resolves its subject and object as the attribute path does, through
  `decode_rdf_representation`, whose `_resolve_iri` registers a namespace the graph binds
  on demand (section 2 shows why: `foaf:Alice` as an agent in N-Triples resolves today
  only because `foaf` was pre-registered). Typed subjects, attribute values and predicates
  already take that path. An untyped relation endpoint whose IRI no graph binding covers,
  such as `urn:uuid:...` as the object of `prov:wasDerivedFrom`, therefore reads under the
  prefix `_resolve_iri` mints (`ns1`, ...), as a typed subject and an attribute object do,
  where on `main` (3f0863e) it raises `ProvExceptionInvalidQualifiedName`; `HISTORY.md`
  lists it under "Fixes" (N45, ruled 2026-10-25). The same holds for an untyped subject,
  and for the subject of a `prov:qualified*` triple, whose name `_decode_triples` stores
  for the qualified relation.
- A literal's datatype IRI resolves as an attribute object does, through `_resolve_iri`
  when the document's namespaces do not compact it, where `_decode_literal_representation`
  consulted the document alone and dropped a datatype none of them compacts (#665). On
  `main` (ed0c9b8) `"1"^^<http://d.example/c:d>`, a default-namespace datatype the writer
  spells in full because no `@prefix :` is written, reads as the plain text `'1'`. It now
  reads under the prefix `_resolve_iri` mints (such as `ns2`, bound to `http://d.example/c:`), which
  names the same IRI, so the `Literal` equals the one written. Without this item the first
  item would drop every datatype under one of rdflib's prefixes, such as
  `"1"^^dcterms:W3CDTF`, which reads on `main` only because `dcterms` was pre-registered. A
  datatype IRI that neither rdflib nor `prov` can split into a namespace and a local part,
  such as `urn:example:t=`, raises as a typed subject with
  that IRI does, where `main` dropped the datatype. `HISTORY.md` lists the fix under "Fixes"
  and the raise under "Changes with no prior warning" (N55, ruled 2026-10-25).
- A namespace the document uses under one of rdflib's prefixes is therefore registered on
  demand with its prefix, and an unused one is not declared. When the reader mints a
  namespace whose IRI is a proper prefix of rdflib's bindings, it registers those bindings
  first, so a name under one keeps its prefix, and those bindings are then declared whether
  used or not (N56). A document that declares a
  prefix and never uses it loses the declaration through PROV-O, which every other format
  keeps; the conformance page's PROV-O section says so, and `get_registered_namespaces()`
  after a PROV-O read no longer lists the defaults.

Tests assert a Turtle round trip declares only the namespaces the document declared, that
a default namespace round-trips as the default, that the N-Triples relation case still
reads `foaf:Alice`, that an untyped `urn:uuid:` relation endpoint reads, and that a
literal keeps a datatype no document namespace compacts. N10 asks whether to file the issue the fix closes; both halves go in
it.

## 7. The model guard (#444)

`Identifier`, `QualifiedName`, `Literal` and `Namespace` are immutable by convention: slots,
`Final` annotations, a hash computed at construction. Nothing stops `q._localpart = "f"`,
after which the cached hash is stale and every set or dict holding the object is corrupt
without a message.

**Rule (N13).** The four classes define `__setattr__` and `__delattr__` that raise
`AttributeError("<Class>.<field> is read-only")` for the class's own slot names and defer
to `object.__setattr__` for any other name, so a subclass that sets its own attributes in
`__init__` (instances of a subclass without `__slots__` carry a `__dict__`, and such code
works today) keeps working, while the fields the hash depends on are guarded. `__init__`
and `__setstate__` assign through `object.__setattr__`, which `__setstate__` already does.
`Namespace._cache` stays a mutable dict, assigned once; its contents change, the slot does
not. The cost is one
`object.__setattr__` call per field at construction: two for `Identifier`, five for a
`QualifiedName` (cached per namespace, 3,800 constructions per 10k-record read), three for
a `Literal`, three for a `Namespace`. The A/B's `construct` and the five readers are the
gate; the issue's own criterion applies (a few percent at most, else make it cheaper or
reconsider). Pickles of 3.2.x objects load as before. Lands last, after the PRs that touch
the constructors.

### 13.1 `prov_to_graph()` flattens, then unifies (#651, PR 18a)

`prov_to_graph()` unifies the document and walks `unified.get_records()`, which returns
the top-level records only, so every record inside a bundle is dropped with no warning and
`graph_to_prov()` cannot bring it back. N26 rules that `prov_to_graph()` and
`graph_to_prov()` work on documents only, and the graph is of the whole document.

**Rule.** `prov_to_graph()` builds the graph from `prov_document.flattened().unified()`.
Every element and relation of the document and of every bundle is a node or an edge,
records that share an identifier across bundles merge under the unification rules, and a
document whose bundles disagree about a shared identifier raises `ProvUnificationError`
from `prov_to_graph()`, where its bundles' records were never seen. `flattened()` already
declares a prefix for each bundle default that differs from the document's (N24), so a bare
name from such a bundle keeps a spelling, and `graph_to_prov()`, which copies the
declarations of the records' document, round-trips the flattened document (probed:
`prefix dn <http://bun.org/>` and `entity(dn:inner)` both ways). `prov_to_dot()` is
untouched: `dot.py` imports `INFERRED_ELEMENT_CLASS` only and calls `bundle.unified()`
itself, so it draws bundles as asserted, and #652 stays unopened.

`graph_to_prov(prov_to_graph(d))` therefore holds the records of `d.flattened().unified()`
less the relations `prov_to_graph()` skips with a `ProvWarning` (one whose first two formal
attributes are not both set), which `test_simple_graph_conversion` asserts as a set of
records once its "cannot round-trip with bundles" skip goes; the two bundle examples hold
four `wasGeneratedBy(e, -, time)` records, two of them top-level, which the skip hid.
`test_round_trip_against_unified_document` goes, its Primer row being in
`test_simple_graph_conversion`. The A/B's `prov_to_graph` case, on a document that holds a
fifth of its records in five bundles, slows by about 50% by the A/B's medians, about 70% by
a direct min-of-7 timing (3040 to 3800 nodes, 4000 to 5000 edges, plus the `flattened()`
copy); the figure is the work the graph used to skip and is reported, not chased. The
docstring and the how-to's "It unifies the document first" sentence say "flattens, then
unifies". `HISTORY.md` lists it under "Changes with no prior warning", beside the
`unified()` deduplication bullet (#548), because graphs of documents with bundles gain nodes
and edges and may now raise (N28).

Ledger expectation: `prov_to_graph` 33 NLOC, CCN 8, unchanged but for one call in the
chain; `test_graphs.py` loses the skip branch and gains the tests of section 10.

### 13.2 A `Literal` built from a Python value takes its lexical form (#656, PR 18b)

`_literal_text(value, datatype)` takes `python_value_form`'s text for a `bool`, a `float`,
a `Decimal` and a `datetime` only, and `str()` for everything else, so
`Literal(timedelta(days=1, seconds=30), XSD["duration"]).value` is `'1 day, 0:00:30'`, a
`UUID` is its hex form without `urn:uuid:`, and bytes are `repr()` text, where the same
values asserted plainly are stored as `P1DT30S`, `urn:uuid:...` and `AAE=` (#482).

**Rule.** A `Literal`'s text is `prov`'s spelling of the value whenever the value has one.
`_literal_text` calls `python_value_form(value)` for every value (a `str` spells as itself,
so the `isinstance` gate goes) and keeps `str()` only for a type with no form or a value
with none, as today. Two datatype-aware rows: a `float` under `xsd:decimal` goes through
`Decimal` as today, and a bytes-like under `xsd:hexBinary` spells as
`bytes(value).hex().upper()`, the canonical uppercase form, the one case the issue names
where the value has a form in the given datatype that differs from the form `prov` chooses
for it. An `int` subclass whose `str()` is not its digits, the `(int, Enum)` member of the
HISTORY bullet, spells as its digits here too. The datatype stays the caller's, `None`
included. No reader builds a `Literal` from a non-string value other than a JSON number or
boolean, whose text is unchanged, so no reader output moves. `HISTORY.md` lists it under
"Fixes".

**The rejection half is declined (N29).** The issue asks that a value with no form in the
given datatype, bytes under `xsd:duration`, raise `ProvValueError`. N3 ruled that a
`Literal` holds the text its caller gave it under the datatype its caller chose, and that
only the plain path, where `prov` picks the form, may refuse, so `Literal(Decimal("NaN"),
XSD_DECIMAL)` stays an ill-formed text. Deciding which `(type, datatype)` pairs have a form
is a new table (`int` under `xsd:string`, `datetime` under `xsd:date`, `True` under
`xsd:int`) with no PROV rule behind it. So bytes under `xsd:duration` stores the base64
text under `xsd:duration`, as the NaN case stores `NaN` under `xsd:decimal`, and the
`Literal` docstring sentence of 3.1 covers it.

Ledger expectation: `_literal_text` 8 NLOC, CCN 6, to 12 and 7 (the hexBinary row adds one
condition, the `isinstance` gate loses one; ruff wraps the hexBinary condition over four
lines); the `test_literal_spells_a_python_value_in_xsd_form` table in
`test_literal_semantics.py` gains seven rows, the `(int, Enum)` and N29 cases among them.
A `str` now takes the `python_value_form` call it skipped, about 170 ns per `Literal`,
under 0.4% of any `deserialize` A/B case.

### 13.4 One exception hierarchy (#653, PR 21a)

The issue's tree: `prov.Error` over `ProvException` (the model refuses an operation), a new
`ProvSerializationError` (a format cannot be read or written) over the five format errors,
and `DoNotExist`. Today the four format errors other than `ProvNSyntaxError` derive from
`prov.Error` directly and `ProvNSyntaxError` from `ProvException`.

**What leaks today.** The issue names PROV-XML. The probe shows every reader but PROV-N
lets the model's exception through: a time offset beyond ±14:00 (`ProvValueError`) from
PROV-JSON, PROV-JSONLD, PROV-XML and PROV-O; a language tag that is not BCP 47
(`ProvValueError`) from PROV-JSON, PROV-JSONLD and PROV-XML; a local part PROV-N cannot write
(`ProvExceptionInvalidQualifiedName`) from PROV-JSON, PROV-JSONLD and PROV-XML; an element
with no identifier (`ProvElementIdentifierRequired`) from PROV-XML; and a `prov:time` with
seven fractional digits (`ProvException`) from PROV-XML. PROV-O raises the model's
`ProvException` for its own #217 shape (`_emit_decoded_records`) and `ProvRDFException` for
"No document to serialize" only, and the PROV-O how-to and the conformance page document
`ProvException` as PROV-O's error. PROV-O's `_split_at_separator` raises a plain
`ValueError` for an IRI that neither `compute_qname` nor a `#` or `/` splits, such as
`urn:example:e2=` as a typed subject or an attribute object (probed on 3f0863e). The PROV-XML reader raises `AssertionError` for a
`bundleContent` with no `prov:id` or outside a document. The PROV-N parser wraps already
(`provn_parser.py` lines 383 to 389 and 414 to 420): its own error passes, and any other
`ProvException` becomes a `ProvNSyntaxError` at the statement with the model's as
`__cause__`.

**Rule.** `prov.serializers.ProvSerializationError(Error)` is the base (N32), in `__all__`
and `PUBLIC_API`; `DoNotExist`, which is in `PUBLIC_API` only, stays as it is. `ProvJSONException`,
`ProvJSONLDException`, `ProvXMLException` and `ProvRDFException` derive from
`ProvSerializationError` alone; `ProvNSyntaxError`, a `ProvException` today, derives from
`(ProvSerializationError, ProvException)` through 3.x and 4.0 drops the second (N33, ruled
2026-10-24). Each reader wraps once, at the record, in the PROV-N parser's
two-clause shape: the format's own error passes, and any other `ProvException` is re-raised
as the format's error naming the record, with the model's sentence in the message and the
model's exception as `__cause__`. The sites are the per-record body of `deserialize_subtree`
(PROV-XML, naming the element and its `prov:id` and, since lxml gives it, the line), the
per-record loop of `_decode_record_group`, which `decode_json_container` calls per record
type (PROV-JSON, `_position(rec_id, None)`), `decode_jsonld_statement` and the `@graph` loop
of `decode_jsonld_document` (PROV-JSONLD, the `@id` and `@type`; a statement inside a bundle
names itself, and the loop names the bundle), and the
three passes of `decode_container` (PROV-O, the subject): `_decode_type_triples` and
`_decode_triples` run `_resolve_iri` and build attribute `Literal`s before
`_emit_decoded_records` builds a record, so a wrap at the last pass alone misses them (N46,
ruled 2026-10-25). `_emit_decoded_records`' existing `except pm.ProvException` relabels the
#217 shape as `ProvRDFException` and wraps the rest instead of re-raising. The two
`AssertionError`s become `ProvXMLException`, and so does the `KeyError` that
`FULL_PROV_RECORD_IDS_MAP` raises for an unknown element in the PROV namespace, naming the
element and its line (N58). `_split_at_separator` raises `ProvRDFException` naming the IRI,
the reader's own refusal (N46). A model exception raised outside record construction, such
as a declaration a reader cannot apply, has no record to name; the plan
lists each such site it finds and wraps it at the document. Two exist on `main` (442c2cb):
PROV-JSON's bundle loop in `decode_json_document` (an unwritable bundle identifier, a

**The default-IRI reason (#675, N57).** A qualified-name value equal to a default
namespace IRI in reach is rejected with #473's sentence ("the IRI ... is the default
namespace and has no qualified-name form; declare a prefix for it") in place of "its

### 13.6 A namespace prefix is a `PN_PREFIX` (#668, PR 21b)

`ProvDocument.add_namespace()` checks no prefix, and the PROV-JSON reader registers
whatever its `"prefix"` object holds, so a prefix a format cannot spell is written as it
stands and the text does not read back. The issue's table across the five formats: a
prefix holding a line feed, a space or a `"` is written raw by PROV-N and read back by
nothing but PROV-JSON and PROV-JSONLD; `a:b` reads back nowhere; `1a` round-trips through
PROV-JSON and PROV-JSONLD only; `_a` everywhere but PROV-N; `a-b` and `a.b` everywhere.
`PN_PREFIX`, the SPARQL production PROV-N's `QUALIFIED_NAME` [52] and Turtle share (a
`PN_CHARS_BASE` first, so no leading digit or `_`, then `PN_CHARS` or `.`, not ending in
`.`), is the narrowest of the five rules, and every `PN_PREFIX` is an NCName, so PROV-XML
writes it too. The maintainer ruled on the issue (N38): the rule is `PN_PREFIX`, the check
is the model's, and a prefix 3.2.3 accepted that does not match now raises.

**What accepts today.** Every model entry point builds a `Namespace`: `add_namespace(prefix,
uri)` (`bundle.py` line 568), the `namespaces=` mapping of both constructors through the
private `NamespaceManager.add_namespaces` (`namespaces.py` line 214; `ProvDocument` has no
public `add_namespaces`), and the clash-rename path (line 186). So does every reader:
PROV-JSON's `_decode_namespaces` (`provjson.py` line 441), PROV-JSONLD's `_decode_context`
(`provjsonld.py` line 421), PROV-XML's `_namespace` at the `bundleContent` element
(`provxml.py` line 394) and on demand at a name (line 921), and PROV-O's `add_namespace`
in `decode_document`'s binding loop (`provrdf.py` line 1366) and in `_resolve_iri`. On
`main` (28adb62) `Namespace()` and each of those paths accept `1a`, `_a`, `a.`, `.a`, `a b`,
a line feed, `a:b` and `a"b`; `prov` and `xsd` are renamed to `prov_1` and `xsd_1` and
`xsi` registers as given. PROV-N refuses already: the lexer rejects `1a:e` at the use, and
`_declarations` (`provn_parser.py` lines 321 to 326) rejects `prefix 1a` and `prefix _a`
with #511's message when no use precedes; its `_PN_PREFIX_NAME` is the lexer's `_PN_PREFIX`
(`provn_lexer.py` line 98), built from the NCName tables the lexer imports from
`prov.identifier`. PROV-JSON and PROV-JSONLD read `1a`, `_a`, `a.` and `a b`; PROV-XML
reads `_a` and `a.`, lxml itself refusing `xmlns:1a`; PROV-O reads `_a` from RDF/XML and
Turtle, rdflib refusing `@prefix 1a:` and `@prefix a.:`. 3.2.3 accepted every prefix at
every entry point, the empty one included. A pickle 3.2.3 wrote of a document with prefix
`1a` or `_a` loads on `main`, writes `prefix 1a` in PROV-N and round-trips through PROV-JSON.

**Rule (N39, N40).** `Namespace.__init__` refuses a prefix that does not match `PN_PREFIX`
with a `ProvValueError` naming the prefix, in the shape `the prefix '1a' is not a
PN_PREFIX, so no format can write it`. One check covers every path above, as #524's
local-part check in `QualifiedName.__init__` covers every path that builds a name, and no
`Namespace` with such a prefix exists, the rename path's `prefix_1` of a valid prefix
included. The pattern moves from `provn_lexer.py` into `identifier.py` beside the NCName
tables it is built from, and the lexer and parser import it; the check takes the fast path
`_reject_unwritable_local_part` takes, an ASCII identifier that does not start with `_`
needing no regex. `Namespace._default` bypasses the constructor; the default is a
declaration with no prefix text and is untouched. The constructor's two other refusals, the
empty prefix of N21 and the blank IRI of `_check_namespace_uri`, raise `ProvValueError` as
well, so the constructor has one class; `ProvValueError` is a `ValueError`, so the N21
bullet of `HISTORY.md` stays true and `except ValueError` keeps working, and it is a
`ProvException`, so the how-to's `except` clause for the model (13.4) catches it.

**The readers (N41).** The PROV-N parser keeps its own check, now on the shared pattern: it
is positioned at the token, its message is #511's, pinned in `REJECTED_DOCUMENTS` and
`HISTORY.md`, and the model's check cannot fire from PROV-N because the parser's precedes
the construction. The four other readers raise the model's `ProvValueError` from inside a
prefix loop, which sits outside the record loops 21a wraps, so 13.4's rule for a model error
raised outside record construction applies: `_decode_namespaces`, `_decode_context` and
`decode_document`'s binding loop each wrap the whole declaration loop as the format's error
at the document, naming the prefix and the IRI, with the model's exception as `__cause__`.
The default branch is inside the wrap: `Namespace._default` runs `_check_namespace_uri`, so
a blank default IRI such as PROV-JSON's `{"default": ""}`, a plain `ValueError` from the
reader on `main` (3f0863e), raises `ProvValueError` too and reads as the format's error
(N49, ruled 2026-10-25). `_decode_context` registers every context key whose value is a
string as a prefix, `"ex:term"`, `"1st"` and `"a b"` included. Every key that is neither a keyword nor a `PN_PREFIX` raises, a key holding
`:` included, which is a JSON-LD term definition PROV-JSONLD does not prescribe (N47 as
amended by N61).
A context value that starts with `@` (such as `"id": "@id"`) is not an IRI, and the reader
refuses it under any key that registers a namespace, `@vocab` and `""` included; the reader
understands no JSON-LD and reads only the structure PROV-JSONLD prescribes (N60). The refusal
is the model's: `_check_namespace_uri` refuses a namespace IRI that starts with `@` with
`ProvValueError`, before the prefix is checked, so no entry point holds a namespace the
PROV-JSONLD reader cannot read back, and the reader raises it through the wrap above (N62). On `main` (47ae5a2) such a
term registers a namespace bound to the keyword, which the PROV-N writer declares as
`prefix id <@id>`.
PROV-XML needs no new wrap: its two sites, `_read_bundle_content` (called from
`deserialize_subtree`'s element loop at line 337) and the name resolution of the per-record
