## 2. Evidence

### 2.1 `Literal` accepts any datatype (#705)

`Literal.__init__` (`src/prov/model/records.py:445`) and `__setstate__` check nothing about
`datatype` beyond the language-tag override; the annotation is `QualifiedName | None`.
Since #704 `Literal._key` reads `datatype.uri`, and every writer calls
`datatype.provn_bare_representation()`. Probed on `main` and on the 3.2.3 wheel:

| Datatype | `main`: construct | `main`: `hash`, `==` | `main`: `str`, assertion on a record | 3.2.3 |
|---|---|---|---|---|
| `"ex:type"` (a `str`) | succeeds | `AttributeError: 'str' object has no attribute 'uri'` | `AttributeError` (`provn_bare_representation`; `namespace` at assertion) | all succeed; writes `"x" %% ex:type` |
| `object()` | succeeds | the same `AttributeError` | the same | all succeed |
| `Identifier("http://example.org/t")` | succeeds | an int; `True` | `AttributeError` (`provn_bare_representation`; `namespace` at assertion) | all succeed; writes `"x" %% http://example.org/t`, which no reader accepts |
| `XSD_STRING` | succeeds | works | works | works |

So `main` fails later than 3.2.3 did, with an `AttributeError` that names a missing
attribute rather than the mistake.

### 2.2 A refused `add_bundle` leaves a namespace behind (#726)

`ProvDocument.add_bundle` (`bundle.py:2040`) links the bundle's namespace manager to the
document, resolves the identifier through `bundle.mandatory_valid_qname`, and on a
`ProvException` restores the parent and re-raises. PR 37 (spec 5, 5.3, F19) added that restore.
The residual: for a `QualifiedName` identifier, `valid_qualified_name` registers the name's
namespace on the bundle's own manager before the duplicate check runs. Probed: after a
refused duplicate (`doc.add_bundle(b2, Namespace("zz", "http://zz.example/")["b"])` with
`zz:b` already held), `b2` has its parent restored and no identifier, but
`b2.get_registered_namespaces()` holds `zz`; the document is unchanged. A string identifier
with an undeclared prefix raises `ProvExceptionInvalidQualifiedName` and leaves nothing on
either side. A successful call registers the namespace on the bundle only.

### 2.3 The order of `PROV_RECORD_ATTRIBUTES` varies (Debian 1148660)

`src/prov/constants.py:234` builds `PROV_RECORD_ATTRIBUTES` from the set `PROV_ATTRIBUTES`,
and `PROV_ID_ATTRIBUTES_MAP` and `PROV_ATTRIBUTES_ID_MAP` from that list.
`Identifier.__hash__` returns a hash of the IRI text, so the set's order follows
`PYTHONHASHSEED`: seeds 1, 2 and 3 give three different orders. `docs/reference/constants.md`
renders the module with `automodule`, and a Sphinx build under two seeds differs in
`reference/constants.html` alone, at the `PROV_RECORD_ATTRIBUTES` entry; `searchindex.js`
is identical. No code path iterates any of the six constants: every use outside
`constants.py` is a membership test or a key lookup (`provrdf.py:432`, `provjson.py:564`
to `:568`, `records.py:1049`, `:1062` and `:1156`, `dot.py`, `provxml.py`,
`provn_parser.py:792`, `provjsonld.py:256` and `:667`). None of the six is in
`PUBLIC_API`; all six are in the frozen `dir(prov.model)` snapshot. Debian's patch (Chris
Lamb, 2026-09-21, wishlist, tagged patch) sorts the set by `str`.

### 2.4 rdflib warns on `.nt` output

`prov-convert doc.provn out.nt` exits 0 and prints
`UserWarning: NTSerializer always uses UTF-8 encoding. Given encoding was: None` from
rdflib 7.6.0's `nt.py:39`. The writer's `serialize` (`provrdf.py:454`) passes `format` and
the caller's keywords to `container.serialize(buf, **newargs)` at line 490 and never sets
`encoding`; rdflib's `Graph.serialize` then hands `encoding=None` to the N-Triples
serializer, whose check is `encoding != "utf-8"`. The `.ttl`, `.nq`, `.trig` and `.rdf`
outputs print nothing. PR 39's review deferred this as B3.

### 2.5 `prov.read()` never returns `None`

`src/prov/__init__.py:218` annotates `read()` as `-> ProvDocument | None`. Its two returns
(`ProvDocument.deserialize(...)` at line 302 and `_detect_and_parse(...)` at line 316) are
both `ProvDocument`; the failure path raises `ProvFormatNotDetected`. No page handles a
`None` result; `docs/howto/read-write.md:55` asserts on the result directly. A strict caller
today needs an `assert loaded is not None` the library never justifies.

### 2.6 `prov-convert` truncates the output before the input reads

`_convert` (`src/prov/scripts/convert.py:383`) opens the input and then the output with
`"wb"` before `convert_file` reads anything. With `out.json` holding `KEEP ME` and an input
that fails to parse (an undeclared prefix, or an unclosed `entity(`), both `main` and the
3.2.3 wheel exit 2 with the parse error on stderr and leave `out.json` at 0 bytes.

### 2.11 A PROV-O read of an IRI typed as an element and a relation (#743)

Added 2026-11-03. `_register_record_type` (`provrdf.py:1636`) types a subject by the first
`rdf:type` triple whose class `_RECORD_TYPE_OF_CLASS` knows and turns every later known
class into a `prov:type` attribute; `register` (`:375`) seeds the formal-attribute slots of
that one type. `_decode_triples` (`:1704`) fills the first slot of the object of a
`prov:qualified*` triple with `next(iter(...))` over those slots, and the qualifier lookup
of `_decode_relation_triple` (`:1798`) indexes the same slots, which an element has none of.
Probed with `ex:e`, `ex:a`, `wasGeneratedBy("ex:e", "ex:a", identifier="ex:g")` and a
second record identified `ex:g`, written and read by prov:

| Second record | PROV-N, PROV-JSON, PROV-XML, PROV-JSONLD | PROV-O on `main` | PROV-O on 3.2.3 |
|---|---|---|---|
| `entity("ex:g")` | round-trips, four records, equal | bare `StopIteration` | the same |
| `agent("ex:g")` | the same | bare `StopIteration` | the same |
| `activity("ex:g")` | the same | `ProvRDFException`, "Invalid value for attribute prov:startTime: ex:e" | `ProvException`, the same sentence |
| `used("ex:a", "ex:e", identifier="ex:g")` | the same | reads three records, unequal | the same |

Which class the reader meets first follows the graph, not the document. A hand-written
Turtle that types `ex:g` as `prov:Generation` before `prov:Entity` reads four records on
`main` and on 3.2.3, the entity lost and a second generation invented. One whose
`prov:qualifiedAssociation` object is typed `prov:Entity` only raises the bare
`StopIteration` on `main` and a bare `IndexError` on 3.2.3. An IRI typed `prov:Entity` and `prov:Agent`, which PROV-DM allows, reads
as one entity with `prov:Agent` as a `prov:type`. `PROV_BASE_CLS` folds `prov:Bundle`,
`prov:Collection`, `prov:Plan`, `prov:Person` and the other subclasses onto their base
type, so a subject typed with a class and its subclass has one record type. Every writer
writes the shared identifier (PROV-O as one node with two `rdf:type` triples), the model
holds both records, and C1 on the conformance page says such a read may give one record or
raise.

### 2.12 A bundle's cached name outlives its document's declarations (#744)

Added 2026-11-03. `NamespaceManager._resolve_cache` (`namespaces.py:82`) maps a plain
string to the name the manager resolved from its own namespaces. `add_namespace`,
`_set_default` and the two writes to `_prefix_renamed_map` (`:216`, `:352`) clear the
manager's own cache and, by the comment at `:79`, not a child's. Since #599
(`_resolve_prefixed_string`, `:371`) a bundle's own answer depends on its document, because
a prefix the document binds stops the bundle compacting the string by IRI. Probed with the
issue's script, on `main` the bundle that resolved `http://ex.org/a` to `q:a` before the
document bound `http` keeps `q:a`, and a bundle made afterwards gives `http://ex.org/a`
under the document's `http` prefix; on 3.2.3 both give `q:a`, because 3.2.3 compacted
without consulting the document. A colon-less string is unaffected, because the bundle's
own default alone resolves it and a parent's answer is never cached in the child (probed,
`x` before and after the document's default changes). Nothing clears a bundle's cache when
`add_bundle` links or restores its parent (3.2). Bundles do not nest, so a manager's chain
is two deep.

## 3. The code loose ends (PR 42, L3)

### 3.1 `Literal` takes a `QualifiedName` or `None` (#705, L9)

A `Literal` whose `datatype` is neither a `QualifiedName` nor `None` raises `ProvValueError`
where it is built and where it is unpickled, with the sentence

    the datatype {datatype!r} of {value!r} is not a QualifiedName

A plain `Identifier` is refused too, because every writer needs the qualified form and the
annotation promises it. The check is one `isinstance` in `__init__` before the language-tag
override, so `Literal("x", "ex:t", "en")` raises where 3.2.3 overrode the datatype with
`prov:InternationalizedString` and a logged warning (L12; one rule, no language-tag
exception), and one in `__setstate__` beside `_check_langtag`. Every reader passes a resolved
name, so no document changes; code that built such a literal, which 3.2.3 accepted, now
fails at the construction with the sentence. The 3.2.3 pickle of such a literal fails to
load with the same sentence. The A/B gate is `construct` and `deserialize` (`ab.py main
--python 3.12`), where the cost is one `isinstance` per literal.

### 3.2 A refused `add_bundle` leaves the bundle as it was (#726)

`add_bundle` refuses a `QualifiedName` identifier that a held bundle already carries, comparing
by IRI, before it links anything. Any other identifier resolves against the bundle's own
namespaces first and then the document's, through the link to the document, and a refusal
restores the bundle's previous parent. The link stays because resolving a string or
`Identifier` registers nothing, while a bundle without the link would read a string whose
prefix the document declares through its own namespaces instead (#599). Only once the name
has resolved and the duplicate check has passed is the bundle added, with the parent linked,
the identifier set and, for a `QualifiedName` from a foreign namespace, that namespace
registered on the bundle (L11). A call that raises, for an identifier no namespace resolves
or one a held bundle already carries, leaves the bundle's parent, identifier and registered
namespaces as they were, and the document is never changed by a refused call. A string
identifier whose prefix only the bundle declares still resolves, as today. The function
stays within Lizard's 14.

### 3.3 `PROV_RECORD_ATTRIBUTES` in one order (Debian 1148660)

`PROV_RECORD_ATTRIBUTES` is built from `PROV_ATTRIBUTES` sorted by `str`, as Debian's patch
does, so the two maps and the rendered reference have one order under every hash seed.
Nothing else changes: no code path iterates the constant (2.3). A Sphinx build of
`reference/constants.html` under two seeds is identical afterwards; the PR body credits
the bug.

### 3.4 `.nt` output without a warning

The PROV-O writer passes `encoding="utf-8"` to rdflib for every RDF format, one keyword
with no table (L14), so the N-Triples serializer's check passes under each of its spellings
(`nt`, `ntriples`, `nt11`, `application/n-triples`) and no `UserWarning` reaches a
`prov-convert` user or a caller of `serialize(format="rdf", rdf_format="nt")`. rdflib writes
UTF-8 to a binary stream in every case; the plan verifies the turtle, trig and nquads bytes
are unchanged, and falls back to the four N-Triples spellings if any output moves.

### 3.5 `prov.read()` returns a `ProvDocument`

The annotation becomes `-> ProvDocument`, and the `cast` with its comment at
`src/prov/scripts/__init__.py:228` goes, since strict mypy reports a redundant cast. The
docstring already says so. A caller's `assert loaded is not None` keeps working and becomes
removable.

### 3.6 `prov-convert` opens the output after the input reads

`prov-convert` reads and parses the input before it opens the output file for writing, so
an input that fails to read leaves an existing output file untouched, with the same exit
status and error line as today. An error while writing may still leave a partial file, as
any writer does; the rule covers reading only. The standard streams are unaffected.
`convert_file`'s signature is unchanged; `_convert` reads the document first and hands the
writer half the output stream, or `convert_file` gains the split, as the plan decides under
the Lizard ceiling.

### 3.7 Tests

The four private `_doc()` helpers go and the modules call `ex_document()` (#671, imported as
`test_attribute_merging.py` imports `roundtrip_document`). `REPO_ROOT` becomes one constant
in `conftest.py`, read by the three modules. No behaviour changes; the suite's counts are
unchanged.

### 3.8 `sorted_attributes` leaves the public API (L13)

`sorted_attributes` is in `PUBLIC_API` with a docstring and on no reference page. It leaves
`PUBLIC_API` and stays where the PROV-XML writer uses it, undocumented; the frozen
`dir(prov.model)` snapshot is unchanged, so an import keeps working. One Project entry says
it is no longer part of the public API.

## 4b. The audit's two defects (PR 44, L17 and L18)

Added 2026-11-03. The audit filed seven behaviour defects (M1); the maintainer kept #743
and #744 in the release as one PR before the freeze (M2) and left the other five to later
releases (L19, section 9).

### 4b.1 The PROV-O reader refuses an IRI that is both an element and a relation (#743, L17)

An IRI whose `rdf:type` triples make it both an element and a relation raises
`ProvRDFException`, whichever class the graph gives first, with the sentence

    subject {iri!r} is typed as both {first} and {second}; an element and a relation cannot share an identifier

where the two classes are written as the reader decodes them (`prov:Entity`,
`prov:Generation`). The check sits where the reader records a subject's type, so the
`StopIteration`, the misleading `prov:startTime` sentence and the silent loss of the entity
in 2.11 all become the one raise. A `prov:qualified*` triple whose object is typed as an
element only, or a qualifier node that a relation's binary triple leads to and that is
typed so, raises the same exception with the predicate in the sentence

    subject {iri!r} is the object of {predicate} but is typed as {type}, which is not a relation

so a graph from another producer fails with a sentence and not with `StopIteration` or
`IndexError`. Both raises come with no cause, since nothing was raised beneath them, and
are C1's raise on the conformance page, whose text already says a read may give one record
or raise.

Nothing else changes. Two elements on one IRI (an entity that is an agent) read as one
record with the second class as a `prov:type`, as today; two relations on one IRI collapse
as C1 says; the writer keeps writing the shared identifier, as #217 ruled; the other four
formats round-trip the shape. `_register_record_type` and `_decode_triples` stay within
Lizard's 14.

### 4b.2 A bundle resolves a string as a fresh bundle would (#744, L18)

A bundle resolves a plain string as a bundle created in its current state would. Every
change to a document's declarations that empties the document's own cache (a namespace
added, the default set, a prefix reading recorded by `_reconcile_qualified_name`) also
invalidates the cache of each bundle that reads through it, and linking, restoring or
removing a bundle's parent (3.2's `add_bundle`) empties the bundle's cache. The comment at
`namespaces.py:79` that a parent's mutation does not clear a child's cache goes with the
rule.

The mechanism is a change count (L18). Each manager counts its declaration changes, a
bundle's cache remembers the count of the parent it was filled under, and a read empties the cache when
the parent's count has moved. No manager holds a reference to its children, a bundle
added later needs nothing, the cost on a hit is one integer comparison, and a pickle from
a release without the count loads through `__setstate__` with a default, as the index
does. A name a record already holds keeps its spelling, because the cache holds only what
a plain string resolves to on its next read.

After the fix the issue's two bundles both give `http://ex.org/a` under the document's
`http` prefix, which is the reading #599 set (a bundle reads a prefix its document binds
and does not compact past it); 3.2.3 gave `q:a` for both. The fix changes nothing visible
against 3.2.3 beyond the #599 rule's own change, so it has no HISTORY entry (section 6).
The A/B gate is `construct` and `deserialize` (`ab.py main --python 3.12`), because
`valid_qualified_name` is the hot path spec 4 tuned.
