## 1. Purpose

This spec closes 3.3.0's build. It delivers the code loose ends the earlier specs deferred,
in one PR, and the pre-release documentation audit, as one PR whose merge is the freeze
commit, and it states the pre-flight that runs on that commit. It closes #705 and #726, the
reproducibility defect Debian reported as bug 1148660, the rdflib warning on `.nt` output,
the over-wide annotation of `prov.read()`, the output file `prov-convert` truncates before
its input reads, `sorted_attributes` as a public name, and the test clean-ups #671 and the
repeated `REPO_ROOT`.

It does not add a PyPy 3.12 CI job (section 9, L4), a public accessor for the registry's
format names, or the release PR's stamps (L1, section 9). It changes no behaviour outside
section 3.

## 2. Evidence

### 2.1 `Literal` accepts any datatype (#705)

`Literal.__init__` (`src/prov/model/records.py:445`) and `__setstate__` check nothing about
`datatype` beyond the language-tag override; the annotation is `QualifiedName | None`.
Since #704 `Literal._key` reads `datatype.uri`, and every writer calls
`datatype.provn_bare_representation()`. Probed on `main` and on the 3.2.3 wheel:

| Datatype | `main`: construct | `main`: `hash`, `==` | `main`: `str`, assertion on a record | 3.2.3 |
|---|---|---|---|---|
| `"ex:type"` (a `str`) | succeeds | `AttributeError: 'str' object has no attribute 'uri'` | `AttributeError` (`provn_bare_representation`; `namespace` at assertion) | all succeed; writes `"x" %% ex:type` |
| `object()` | succeeds | the same `AttributeError` | the same | all succeed |
| `Identifier("http://example.org/t")` | succeeds | an int; `True` | `AttributeError` (`provn_bare_representation`; `namespace` at assertion) | all succeed; writes `"x" %% http://example.org/t`, which no reader accepts |
| `XSD_STRING` | succeeds | works | works | works |

So `main` fails later than 3.2.3 did, with an `AttributeError` that names a missing
attribute rather than the mistake.

### 2.2 A refused `add_bundle` leaves a namespace behind (#726)

`ProvDocument.add_bundle` (`bundle.py:2040`) links the bundle's namespace manager to the
document, resolves the identifier through `bundle.mandatory_valid_qname`, and on a
`ProvException` restores the parent and re-raises. PR 37 (spec 5, 5.3, F19) added that restore.
The residual: for a `QualifiedName` identifier, `valid_qualified_name` registers the name's
namespace on the bundle's own manager before the duplicate check runs. Probed: after a
refused duplicate (`doc.add_bundle(b2, Namespace("zz", "http://zz.example/")["b"])` with
`zz:b` already held), `b2` has its parent restored and no identifier, but
`b2.get_registered_namespaces()` holds `zz`; the document is unchanged. A string identifier
with an undeclared prefix raises `ProvExceptionInvalidQualifiedName` and leaves nothing on
either side. A successful call registers the namespace on the bundle only.

### 2.3 The order of `PROV_RECORD_ATTRIBUTES` varies (Debian 1148660)

`src/prov/constants.py:234` builds `PROV_RECORD_ATTRIBUTES` from the set `PROV_ATTRIBUTES`,
and `PROV_ID_ATTRIBUTES_MAP` and `PROV_ATTRIBUTES_ID_MAP` from that list.
`Identifier.__hash__` returns a hash of the IRI text, so the set's order follows
`PYTHONHASHSEED`: seeds 1, 2 and 3 give three different orders. `docs/reference/constants.md`
renders the module with `automodule`, and a Sphinx build under two seeds differs in
`reference/constants.html` alone, at the `PROV_RECORD_ATTRIBUTES` entry; `searchindex.js`
is identical. No code path iterates any of the six constants: every use outside
`constants.py` is a membership test or a key lookup (`provrdf.py:432`, `provjson.py:564`
to `:568`, `records.py:1049`, `:1062` and `:1156`, `dot.py`, `provxml.py`,
`provn_parser.py:792`, `provjsonld.py:256` and `:667`). None of the six is in
`PUBLIC_API`; all six are in the frozen `dir(prov.model)` snapshot. Debian's patch (Chris
Lamb, 2026-09-21, wishlist, tagged patch) sorts the set by `str`.

### 2.4 rdflib warns on `.nt` output

`prov-convert doc.provn out.nt` exits 0 and prints
`UserWarning: NTSerializer always uses UTF-8 encoding. Given encoding was: None` from
rdflib 7.6.0's `nt.py:39`. The writer's `serialize` (`provrdf.py:454`) passes `format` and
the caller's keywords to `container.serialize(buf, **newargs)` at line 490 and never sets
`encoding`; rdflib's `Graph.serialize` then hands `encoding=None` to the N-Triples
serializer, whose check is `encoding != "utf-8"`. The `.ttl`, `.nq`, `.trig` and `.rdf`
outputs print nothing. PR 39's review deferred this as B3.

### 2.5 `prov.read()` never returns `None`

`src/prov/__init__.py:218` annotates `read()` as `-> ProvDocument | None`. Its two returns
(`ProvDocument.deserialize(...)` at line 302 and `_detect_and_parse(...)` at line 316) are
both `ProvDocument`; the failure path raises `ProvFormatNotDetected`. No page handles a
`None` result; `docs/howto/read-write.md:55` asserts on the result directly. A strict caller
today needs an `assert loaded is not None` the library never justifies.

### 2.6 `prov-convert` truncates the output before the input reads

`_convert` (`src/prov/scripts/convert.py:383`) opens the input and then the output with
`"wb"` before `convert_file` reads anything. With `out.json` holding `KEEP ME` and an input
that fails to parse (an undeclared prefix, or an unclosed `entity(`), both `main` and the
3.2.3 wheel exit 2 with the parse error on stderr and leave `out.json` at 0 bytes.

## 3. The code loose ends (PR 42, L3)

### 3.1 `Literal` takes a `QualifiedName` or `None` (#705, L9)

A `Literal` whose `datatype` is neither a `QualifiedName` nor `None` raises `ProvValueError`
where it is built and where it is unpickled, with the sentence

    the datatype {datatype!r} of {value!r} is not a QualifiedName

A plain `Identifier` is refused too, because every writer needs the qualified form and the
annotation promises it. The check is one `isinstance` in `__init__` before the language-tag
override, so `Literal("x", "ex:t", "en")` raises where 3.2.3 overrode the datatype with
`prov:InternationalizedString` and a logged warning (L12; one rule, no language-tag
exception), and one in `__setstate__` beside `_check_langtag`. Every reader passes a resolved
name, so no document changes; code that built such a literal, which 3.2.3 accepted, now
fails at the construction with the sentence. The 3.2.3 pickle of such a literal fails to
load with the same sentence. The A/B gate is `construct` and `deserialize` (`ab.py main
--python 3.12`), where the cost is one `isinstance` per literal.

### 3.2 A refused `add_bundle` leaves the bundle as it was (#726)

`add_bundle` resolves the identifier against the bundle's own namespaces first and then
the document's, with nothing linked and nothing registered, then checks for a duplicate,
and only then adds the bundle: the parent is linked, the identifier is set and, for a
`QualifiedName` from a foreign namespace, that namespace is registered on the bundle (L11);
as built, a `QualifiedName` is checked for a duplicate by IRI before the bundle is linked,
and a string or `Identifier` resolves through a link that a refusal restores, since its
resolution registers nothing and an unlinked read would compact a prefix the document
declares (#599). A call that raises, for an identifier no namespace resolves or one a held
bundle already carries, leaves the bundle's parent, identifier and registered namespaces as
they were, and the document is never changed by a refused call. A string identifier whose
prefix only the bundle declares still resolves, as today. The function stays within
Lizard's 14.

### 3.3 `PROV_RECORD_ATTRIBUTES` in one order (Debian 1148660)

`PROV_RECORD_ATTRIBUTES` is built from `PROV_ATTRIBUTES` sorted by `str`, as Debian's patch
does, so the two maps and the rendered reference have one order under every hash seed.
Nothing else changes: no code path iterates the constant (2.3). A Sphinx build of
`reference/constants.html` under two seeds is identical afterwards; the PR body credits
the bug.

### 3.4 `.nt` output without a warning

The PROV-O writer passes `encoding="utf-8"` to rdflib for every RDF format, one keyword
with no table (L14), so the N-Triples serializer's check passes under each of its spellings
(`nt`, `ntriples`, `nt11`, `application/n-triples`) and no `UserWarning` reaches a
`prov-convert` user or a caller of `serialize(format="rdf", rdf_format="nt")`. rdflib writes
UTF-8 to a binary stream in every case; the plan verifies the turtle, trig and nquads bytes
are unchanged, and falls back to the four N-Triples spellings if any output moves.

### 3.5 `prov.read()` returns a `ProvDocument`

The annotation becomes `-> ProvDocument`, and the `cast` with its comment at
`src/prov/scripts/__init__.py:228` goes, since strict mypy reports a redundant cast. The
docstring already says so. A caller's `assert loaded is not None` keeps working and becomes
removable.

### 3.6 `prov-convert` opens the output after the input reads

`prov-convert` reads and parses the input before it opens the output file for writing, so
an input that fails to read leaves an existing output file untouched, with the same exit
status and error line as today. An error while writing may still leave a partial file, as
any writer does; the rule covers reading only. The standard streams are unaffected.
`convert_file`'s signature is unchanged; `_convert` reads the document first and hands the
writer half the output stream, or `convert_file` gains the split, as the plan decides under
the Lizard ceiling.

### 3.7 Tests

The four private `_doc()` helpers go and the modules call `ex_document()` (#671, imported as
`test_attribute_merging.py` imports `roundtrip_document`). `REPO_ROOT` becomes one constant
in `conftest.py`, read by the three modules. No behaviour changes; the suite's counts are
unchanged.

### 3.8 `sorted_attributes` leaves the public API (L13)

`sorted_attributes` is in `PUBLIC_API` with a docstring and on no reference page. It leaves
`PUBLIC_API` and stays where the PROV-XML writer uses it, undocumented; the frozen
`dir(prov.model)` snapshot is unchanged, so an import keeps working. One Project entry says
it is no longer part of the public API.

### 4.6 Process (P1)

PR 43 runs the review regime as every PR does, with one addition. After the regime's
`/simplify` round the maintainer reads the revised pages and gives feedback in chat; the
coordinator applies the amendments; a review round over the amendments alone checks
accuracy against the code, consistency across pages and readability; then the PR opens,
with the regime's final mark on that last HEAD. The gate runner is rerun after every
amendment commit.

## 5. The freeze and the pre-flight

PR 43's merge commit is the freeze. After the freeze commit nothing merges before the
release PR; a fix the release-wide review or A/B demands rides the release PR, as spec 3
section 9 and spec 5 section 8 set. On the freeze commit, as spec 1 section 7.3 and spec 5
section 6 state and `docs/releasing.md` section 1 lists:

- the release-wide `/code-review high` over the diff from the `3.2.3` tag (L16), run as
  several path-targeted invocations (`src/prov/model`, `src/prov/serializers`,
  `src/prov/scripts` with `src/prov/__init__.py`, the tests) with one merged findings table,
  since the point of the pass is the cost that adds up across PRs;
- `uv run python benchmarks/ab.py 3.2.3 --python 3.12`, then the same with `--gc`, on a
  quiet machine; the release's HISTORY performance paragraph quotes the first run and the
  second only where a benchmark differs by more than four points;
- the own-warnings run, which must raise no `DeprecationWarning`, `PendingDeprecationWarning`
  or `FutureWarning` of prov's own;
- `uv build` with the wheel listing, and the suite counts compared with the last PR's.

The release PR, the 3.2.x-branch question, the milestone close-out and the stamps follow the
runbook and are outside this spec (L1).
