# Release 3.3.0, spec 2: equality and typing

Written 2026-10-22 against `main` 98f0f36 (every build PR of spec 1 merged, PR 14
included). The maintainer took the rulings in section 8 on 2026-10-22; two independent
reviews follow before the spec is committed and any PR is cut from it. Spec 1 is
`2026-10-20-release-3.3.0-design.md`; its section 2 schedules this spec, and its section
11 carries D11 (#548 rolls with the equality stream).

## 1. Purpose

Two streams remain on the 3.3.0 milestone after spec 1.

The equality stream makes `==` on records, documents and literal values one rule, stated
once, symmetric, and consistent with `hash()`: #525 (a record without an identifier equals
one with), document equality (a document ignores the other document's extra bundles),
#527 (literal
equality depends on the datatype and on which reader produced the value), #593, #594 and
#595 (three defects of the `xsd:decimal` comparison), and #548 with #124 (`unified()` keeps
exact repeats). It lands whole or not at all (spec 1, section 2), because each item changes
`==` with no warning and downstream suites should break once.

The typing stream is additive: #491 (four public return types looser than the runtime),
#492 (namespace arguments reject a mapping that is not a `dict`), and the enforceable part
of #494 (the mypy override list only shrinks). It may land piecemeal.

#514 (`xsd:dateTime` range and precision) is explained here and ruled on; the own datetime
type it would need is spec 3's.

## 3. The equality stream

### 3.1 Record equality (#525)

`ProvRecord.__eq__` compares the type, the identifier and the typed attributes. The
identifier is always compared; `None` equals only `None`. `__hash__` already hashes the
identifier, so `a == b` now implies `hash(a) == hash(b)`.

Consequence in `ProvBundle.__eq__`: the record-by-record search after the set comparison
exists only because `__eq__` was looser than `__hash__`. It goes. Bundle equality is
`set(self.get_records()) == set(other.get_records())`, O(n), and the comment that
explains the slow path goes with it. `test_anonymous_relation_still_equals_identified_relation`
in `test_model.py` goes; a symmetric test takes its place (section 6).

### 3.2 Document equality

`ProvDocument.__eq__` checks that every bundle of the left-hand document exists in the
right-hand one with equal contents and never looks at the right-hand document's other
bundles, so a document with an extra bundle on the right compares equal and the swapped
operands compare unequal. It compares the bundle identifier sets before the bundles'
contents: `self._bundles.keys() != other._bundles.keys()` returns `False` first. The
tests cover zero against one bundle, one against two, and different identifiers with
equal counts, with and without top-level records. The fix carries no issue reference.

### 3.3 One key for every attribute value (#527, #593, #594, #595)

**Rule.** Two attribute values are the same value when they have the same datatype and
the same value in that datatype's value space; an ill-formed text has no value and
compares as text. One function gives every value its key, and record equality, record
hashing and the per-attribute value set all use it:

| Value held | Key |
|---|---|
| `str` | `(xsd:string, text, None)` |
| `bool` | `(xsd:boolean, value, None)` |
| `int` | `(canonical_xsd_datatype(value), value, None)`: `xsd:int`, `xsd:long` or `xsd:integer` by magnitude, as the writers type it |
| `float` | `(xsd:double, value, None)`; a NaN takes the text `NaN` as its value slot, since a `float` NaN is never equal to itself |
| `datetime`, `QualifiedName` | `(type, value, None)` |
| any other object | `(type, value, None)`, since the value set's membership test can be handed anything |
| `Literal` with a datatype in the table below and well-formed text | `(datatype, value-space value, None)` |
| any other `Literal` | `(datatype, text, case-folded language tag)` |

Every key is a three-tuple of the same shape, so a plain `5` and a `Literal("05",
XSD_INT)` give one key, `(xsd:int, 5, None)`, and a record holding either equals a record
holding the other.

The datatypes with a value space, each with its XSD 1.1 lexical grammar checked by one
regular expression before conversion:

| Datatype | Lexical form (XSD 1.1 Part 2) | Value |
|---|---|---|
| `xsd:integer` and its twelve subtypes (`long`, `int`, `short`, `byte`, the four unsigned, `nonNegativeInteger`, `nonPositiveInteger`, `positiveInteger`, `negativeInteger`) | `[+-]?[0-9]+`, within the subtype's range (3.4.x) | `int` |
| `xsd:decimal` | `[+-]?([0-9]+(\.[0-9]*)?|\.[0-9]+)` (3.3.3); no exponent, `NaN` or `INF` | `Decimal`, converted in a local context with `InvalidOperation` trapped |
| `xsd:double`, `xsd:float` | `[+-]?([0-9]+(\.[0-9]*)?|\.[0-9]+)([eE][+-]?[0-9]+)?`, `[+-]?INF`, `NaN` (3.3.5, 3.3.4) | `float`; `NaN` takes the text `NaN` as its value |
| `xsd:boolean` | `true`, `false`, `1`, `0` (3.3.2) | `bool` |

What this settles:

- `"5"` and `"05"` as `xsd:int`, `"5"` and `"+5"` as `xsd:long`, `"1e0"` and `"1.0E0"`
  as `xsd:float`, `"true"` and `"1"` as `xsd:boolean`, `"1.0"` and `"1.00"` as
  `xsd:decimal`: one value each. Two documents that differ only in such spellings are
  equal, and so are a document and its PROV-O round trip, where rdflib has rewritten
  the spellings.
- `"NaN" %% xsd:double` is the same value as itself, so a document holding it equals its
  copy and a repeated NaN is one value in an attribute set. XSD 1.1 Part 2 (3.3.5, the
  double value space) defines equality so that `NaN ≠ NaN` and identity so that NaN is
  identical to itself; a PROV
  instance is a set of statements (PROV-CONSTRAINTS 2.3), and set membership is
  identity, so `prov` compares by identity. Two departures: `0` and `-0`, which XSD
  calls equal but not identical and Python's `float` cannot tell apart; and `xsd:float`,
  whose XSD value is the nearest single-precision number while `prov` keys it as a
  Python `float`, so two texts that differ beyond single precision are two values here.
- `"NaN"`, `"Infinity"` and `"1e1"` as `xsd:decimal` are ill-formed (#594), so they
  compare as text; `"sNaN"` never reaches `Decimal()` (#593); and because only text the
  grammar admits reaches `Decimal()`, whose construction from such text is exact in every
  context, the result no longer depends on the caller's context (#595); the local context
  is a guard. `test_ill_formed_decimal_literals_compare_lexically` stays true.
- A `Literal("5", xsd:long)` and a plain `5` are two values (`xsd:long` against
  `xsd:int`), so #235 holds, and `2` against `2.0` holds (#34). XSD puts a derived
  type's values in its base type's value space, so `5` as `xsd:int` and as `xsd:integer`
  are one value there; `prov` keys on the asserted datatype, as #235 ruled, so they stay
  two.
- `Literal("05", XSD_INT) == 5` stays `False` at the object level: the two have different
  Python types and hashes, and cross-type `==` with `int` would break `hash`. The record
  that holds either is equal to the record that holds the other, because records compare
  by key. Asserting both on one attribute keeps the first (`TypedValueSet` keys by the
  same function), as asserting `2` twice does.

**Keeping the lexical form.** A typed literal is collapsed to a Python value at assertion
only when its text is the canonical spelling of that value, the one the writers would
produce (`str(int)`, `_xsd_double_text(float)`, `true` or `false`). Any other
well-formed text stays a `Literal` with its text, compares and hashes by its value, and
is written back as it was read. So `"05" %% xsd:int` reads as `Literal("05", XSD_INT)`
and is written as `"05" %% xsd:int` by PROV-N, PROV-JSON, PROV-JSONLD and PROV-XML
(probed under prototype C), and as `5` by PROV-O, which cannot keep it. Where 3.2.3 read
`"05" %% xsd:int` as `5` and wrote `5`, 3.3.0 keeps the text. `get_attribute()` on such
an attribute returns the `Literal` where it returned an `int`; an unwarned stored-type
change, listed in `HISTORY.md` as D9's were. The lexical form of an `xsd:dateTime` is not
kept (`datetime` holds the value); #514 and spec 3 own that.

**`Literal(value)` spells a Python value in XSD form.** `Literal.__init__` keeps
`str(value)` for a `str`, spells a `bool` as `true` or `false`, a `float` given as
`xsd:decimal` with the decimal text of 5.7 (`format(Decimal(repr(value)), "f")`, so
`Literal(1e16, XSD_DECIMAL)` is `"10000000000000000"`, not the ill-formed `"1e+16"`),
and any other `float` with `_xsd_double_text` (`INF`, `-INF`, `NaN`, `repr` otherwise).
Today `Literal(True, XSD_BOOLEAN).value` is `"True"` and `Literal(float("inf")).value`
is `"inf"`, both outside the lexical space, and the PROV-O reader builds exactly those
from rdflib's coerced values. With the spelling fixed the reader needs no change: every
literal it hands the model is canonical and collapses as before. The `value` property
changes for those inputs; the changelog bullet of 3.7 names the three spellings.

**Where the code goes.** The key function and the lexical table live in
`prov.model._values` (spec 1 put the value checks there, 4.2); `Literal._comparison_value`
calls the table; `ProvRecord._typed_attributes` and `TypedValueSet` call the key. The
`_typed_attributes` docstring (keying on `type(value)`, #34) and the `TypedValueSet`
docstring are rewritten to state the key. `XSD_DATATYPE_PARSERS` and
`_convert_typed_literal` keep their shape; the canonical-spelling check is one comparison
after the parse.

### 3.4 The PROV-O reader and blank nodes

A relation whose subject is a blank node reads as an anonymous record. Today
`_decode_triples` keys every subject by `str(node)` and `_emit_decoded_records` passes
that string to `new_record()` as the identifier, so an anonymous `used` with an extra
attribute, written as a blank `prov:qualifiedUsage` node, comes back with the blank
node's label as its identifier (resolved in the default namespace when there is one).
Under 3.1 that record is no longer equal to the one asserted. `_DecodeState` records
which subjects are blank, and `_emit_decoded_records` passes `None` for them. A blank-node
subject typed as an element keeps today's behaviour: its label resolves in the default
namespace, and a document with no default namespace fails to read with
`ProvElementIdentifierRequired`; the change is for relations only. Every relation family
the writer gives a blank node reaches `_emit_decoded_records`, the one emission point, so
the rule covers them all. This is the change that keeps
`default-namespace-attributes.trig` in the written-by-3.2.3 fixtures reading equal, so the
compatibility test exercises it. The four `test_anonymous_qualified_relation_*` tests in
`test_rdf.py` already pass under prototype A; a `used` with extra attributes joins their
table.

### 3.5 Deduplication in `unified()` (#548, #124)

After the merge by identifier, `_unified_records` keeps each record once: a record equal
to an earlier one, by the `==` of 3.1, is dropped and the earlier one keeps its position.
This applies on both branches of the method, the early return when no identifier is
shared included. It holds for every record kind, as the default, with no option; two
anonymous relations that differ in one attribute or in an absent formal are two
statements and both stay. The `ROADMAP.md` row ("a deduplication option for relations")
is edited in the release PR to describe the default. #124 closes with #548.

Tests that move: `test_equal_keyless_relations_sharing_an_identifier_stay_two`
(`test_unification_rules.py`) and `test_equal_memberships_sharing_an_identifier_give_two_edges`
(`test_graphs.py`) pinned 3.2.3's "stay two until 3.3.0" and now assert one;
`_expected_unified_count` in `test_unification_constraints.py` subtracts the exact
repeats, which moves six corpus files (`association-success5`, `attribution-success4`,
`communication-success4`, `delegation-success5`, `influence-success4`,
`mention-success2`). `docs/explanation/unification-flattening.md`'s "records with no
identifier at all pass through untouched" is rewritten.

### 3.6 `xsd:dateTime` range and precision (#514)

Two limits, measured on `main`. A year outside 1 to 9999 (`10000-01-01T00:00:00`,
`-0044-03-15T00:00:00`, `0000-01-01T00:00:00`) passes the lexical check and fails
`datetime.fromisoformat`, so `parse_xsd_datetime` returns `None` and a formal time raises
`ProvException: Invalid xsd:dateTime value` while an ordinary attribute keeps the
`Literal`. A fraction of more than six digits (`.123456789`) is truncated to microseconds
on read, silently, so the value written back differs from the one read.

The range limit is honest: the input is rejected with a clear message. The truncation is
not. Two options:

- (a) Document both limits on the conformance page and keep the truncation.
- (b) Reject a fraction longer than six digits. The limit is applied in
  `parse_xsd_datetime`, after the lexical match and before `fromisoformat`, so
  `XSD_DATETIME_PATTERN` and the PROV-N lexer's token are unchanged; the function returns
  `None` for the text as it does for a year outside 1 to 9999, so each reader reports it as it reports any text outside the lexical form
  (the #513 bullet in `HISTORY.md` is the model): the PROV-N reader raises
  `ProvNSyntaxError` ("invalid xsd:dateTime") at the token, the PROV-JSON reader
  `ProvJSONException` ("expected an xsd:dateTime"), the model `ProvException` for a
  formal time given in code, and an ordinary attribute keeps the `Literal` from every
  reader. The PROV-JSONLD reader assigns the parser's result with no `None` check
  (`provjsonld.py`, the formal-attribute branch of its item decoder), and
  `add_attributes` skips a `None`, so today a time it cannot parse is read as absent and
  the document loads without it; it gains the check and a row in its rejection table.
  An unwarned change under the D13 precedent, listed in `HISTORY.md` and in the how-to
  ("write at most six fractional digits").

Either way the limits go on the conformance page, and a datetime type of `prov`'s own,
with the full XSD range and precision, is spec 3's (D12 gave #473 the same route).
(b) is the ruling (E10). A provenance timestamp that silently loses digits is the worse
outcome, and an ordinary attribute that keeps the text as a `Literal` loses nothing.

## 4. The typing stream

### 4.1 Return types (#491)

- `ProvBundle.get_records()` returns a `list` in both branches (the filtered branch
  `list(filter(...))`), with two overloads: no argument gives `list[ProvRecord]`; a
  class argument `type[_R]` gives `list[_R]`. The three in-package callers (`graph.py`,
  `dot.py`, `__init__.py`) take a list. A tuple argument gives `list[ProvRecord]`.
- `ProvDocument.bundles` returns `ValuesView[ProvBundle]`; `ProvBundle.bundles` keeps
  raising and takes the same annotation.
- `ProvDocument.serialize()` gets three overloads keyed on `destination`: `None` gives
  `str`, a stream or path gives `None`, and the union `StreamOrPath | None` gives
  `str | None`, so a caller holding either still type-checks.
- `ProvElement.identifier` overrides the property with return type `QualifiedName`;
  relations keep `QualifiedName | None`.
- The chaining methods on `ProvEntity`, `ProvActivity` and `ProvAgent` (`wasGeneratedBy`,
  `used`, `actedOnBehalfOf` and the rest) return `typing.Self`, as the maintainer's
  comment on #491 extends it; additive.
- The tuple argument of `get_records()` is `tuple[type, ...]`, not today's one-element
  `tuple[type]`.

Each narrows a return type; a subclass that overrides with the looser type breaks under
mypy, which the changelog says. About 88 of the suite's strict errors clear with this.

### 4.2 Namespace mappings (#492)

`NSCollection` becomes `Mapping[str, str] | Iterable[Namespace]`, and
`NamespaceManager.add_namespaces` tests `isinstance(namespaces, Mapping)` and reads
`items()`. `ProvBundle(namespaces=...)`, `ProvDocument(namespaces=...)` and
`add_namespaces()` share the dispatch, so all three accept a `MappingProxyType`.

### 4.3 The override list (#494)

The list has 32 entries on `main` after PR 14, and the suite has about 1,000 strict
errors: 434 `no-untyped-def`, 357 `no-untyped-call`, 60 `union-attr`, 47 `arg-type`, the
rest small. 3.3.0 ships the enforceable rule and the cheap modules; #494 stays open for
the rest.

- A test, `test_mypy_override_list_only_shrinks` in `test_public_api.py`, reads
  `pyproject.toml` with `tomllib` and asserts the list equals a frozen snapshot in the
  test. Adding a name fails, and so does removing one until the snapshot moves in the
  same PR, so the snapshot cannot drift and a removed module cannot return.
- The modules whose remaining errors are annotations alone, or clear with 4.1, leave the
  list in the typing PR: `test_json` (6), `test_malformed` (2), `test_json_schema` (2),
  `test_xml_schema` (4), `test_public_api` (1), `test_property_roundtrip` (1),
  `strategies` (6, annotation-only, with a check that the generated corpus is unchanged),
  `test_qnames` (25), `test_attributes` (14), `test_identifier_slots` (6),
  `test_jsonld_schema` (7), `test_jsonld_semantics` (8). `test_statements` (303) and the
  rest wait.

## 6. Tests

- A symmetry and hash table in `test_model.py`: for each pair (identified against
  anonymous relation; document with an extra bundle; a record holding `5` against one
  holding `Literal("05", XSD_INT)`; literal spellings from the datatype table; NaN
  against NaN; `0` against `-0`; a `ProvBundle` against a `ProvDocument` with the same
  records, which `ProvBundle.__eq__` accepts and `ProvDocument.__eq__` refuses today),
  `a == b` and `b == a` agree and, where equal, hashes agree. For the last pair the
  rule is that a bundle and a document are never equal. The pins listed in section 2 are reversed in the same commit as
  the code they pinned.
- A Hypothesis property in `test_property_roundtrip.py`: one record is drawn from
  `strategies.py` and a second derived from it by re-spelling each well-formed literal
  text (a leading `+` or `0`, an exponent, `1` for `true`), and the two compare equal
  with equal hashes in both directions; two independent draws would almost never be
  equal.
  `strategies.py` draws plain ints, booleans, finite floats, strings and datetimes and
  no `Literal` or identified relation, so the value strategy gains typed literals drawn
  from the datatype table (well-formed and ill-formed text) and the relation strategy an
  optional identifier; the generated round-trip corpus is checked unchanged for the
  existing draws. That is the bug class of #525 and #594.
- A spelling table in `test_literal_semantics.py`, one row per pair in the datatype
  table, asserting value equality, equal hashes, the kept text through the four
  text formats, and the rewritten text through PROV-O.
- `test_value_forms.py` gains the ill-formed rows (`sNaN`, `NaN`, `Infinity`, `1e1` as
  `xsd:decimal`; `True` as `xsd:boolean`) asserting text comparison, and a row that the
  decimal context does not change the result.
- Deduplication: the two reversed pins, the six corpus files, and one test that a repeat
  differing by one attribute stays.
- The PROV-O blank-node test: an anonymous `used` with an extra attribute round-trips
  anonymous.
- Typing: a module per 4.1 overload under `mypy --strict` (the tests themselves are the
  check), a `MappingProxyType` test for 4.2, and the override-list test.

All settled 2026-10-22 by the maintainer.

| | Question | Decision |

| E2 | Document equality compares bundle key sets first (3.2) | Yes |
| E4 | One value key for every attribute value, with the XSD 1.1 lexical table (3.3) | Yes |
