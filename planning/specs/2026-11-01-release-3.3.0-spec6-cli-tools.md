# 3.3.0 spec 6: the command-line tools, design (2026-11-01)

Status: approved on 2026-11-01, every decision ruled; PRs 39 to 41 to build. Spec 5 (section 10) left #667 and #684
to this spec, which decides their scope and ships them in 3.3.0. The loose ends outside the
command-line tools (#705, #726, the Debian reproducibility fix, the PyPy 3.12 job, the
release docs audit) and the release step go to spec 7 (C1, C9).

## 1. Purpose

This spec delivers `prov-convert` and `prov-compare` as the tools a 2026 command line
expects, for the people who convert and compare PROV files in shell pipelines, in test
suites and in editors. It closes #667 (writer options on the command line) and #684 (coloured
PROV-N on a terminal), and it finishes #83 (man pages), closed in 2.4.0 by a how-to page,
with a reference page and a man page per tool. It modernises the two scripts, which are the
2014 PyDev template with fixes layered on, and gives both tools format detection in place of
the fixed `json` default.

It does not change what any reader accepts or any writer produces; the tools gain only ways
to reach what the library already does. It does not rename `-i` and `-f`, add shell
completion or a structural diff (#629), teach the library to detect a format from a file
extension, or ship man pages in the wheel (section 11).

## 2. Evidence

### 2.1 The scripts today

`src/prov/scripts/convert.py` (266 lines) and `compare.py` (168 lines) share the 2014 PyDev
console-script template. Each carries `__version__ = 0.1`, `__date__`, `__updated__`,
`DEBUG`, `TESTRUN` and `PROFILE` globals, an unused module logger, an empty `__all__`, a
`CLIError` whose message is prefixed `E: `, and an `if __name__ == "__main__"` block that
runs doctest or cProfile on those flags. `main(argv)` appends `argv` to `sys.argv` and then
parses `sys.argv`. `--help` prints argparse's usage line and then a copyright banner ending in the word
`USAGE`. A runtime error prints `prov-convert: E: <message>` and then `for help use --help`,
indented under the program name, with no trailing newline; `compare.py` defines `CLIError`
and never raises it. `prov-convert` returns 0 on `KeyboardInterrupt`; `prov-compare` lets it propagate
with a traceback. The format lists in the help text are typed by hand.

Lizard (`uvx lizard -C 14`): `convert.main` CCN 10, NLOC 66; `convert.convert_file` CCN 5,
NLOC 22; `compare.main` CCN 11, NLOC 60; `scripts._open_binary` CCN 3, NLOC 10. No function
is over the ceiling. `test_scripts.py` holds 31 tests and `test_cli_smoke.py` 4, which call
`main()` in-process and the console scripts as subprocesses.

`convert_file()` writes `provn` through `get_provn()` directly, a Graphviz name through
`prov_to_dot(...).create(format=...)`, and every other format through `serialize()`. It
passes no option to any of the three.

### 2.3 Writer and reader options today

The `Serializer` base class declares `deserialize_options: ClassVar[frozenset[str]]`, and
`prov.read()` checks a keyword against the chosen reader's set, raising `TypeError` with
"the 'provn' deserializer accepts no option 'x'; it accepts: profile"; under auto-detection
each candidate receives only the options it declares. No serializer declares writer options.

| Format | `serialize` keywords | `deserialize_options` |
|---|---|---|
| provn | `strict: bool = False`, `width: int \| None = 80` | `profile` |
| rdf | `rdf_format: str = "trig"`, `PROV_N_MAP`, rdflib's `Graph.serialize` keywords | `rdf_format`, `relation_mapper`, `predicate_mapper` |
| xml | `force_types: bool = False` | none |
| json | `json.dump`'s keywords | `object_hook`, `object_pairs_hook`, `parse_float`, `parse_int`, `parse_constant` |
| jsonld | `context` (`"url"` or `"embed"`), popped from `**args`, then `json.dump`'s keywords | the same five |
| Graphviz names | `prov_to_dot`'s `show_nary`, `use_labels`, `direction`, `show_element_attributes`, `show_relation_attributes` | |

The five JSON reader options are callables, which no command line can carry. Every
`serialize()` and `deserialize()` takes `**args`, and `ProvDocument.deserialize()` checks
nothing, so an unknown keyword passed to either is swallowed unless the caller checks it;
only `prov.read()` checks, and only when `format` is given. Under auto-detection it filters
per candidate and drops a name no candidate declares, silently.

### 2.4 Detection in the library

`prov.read(source, format=None)` detects by content only. It tries the registry's order,
`json, rdf, provn, xml, jsonld`, rewinding a seekable stream between candidates; a
non-seekable stream is consumed by the first candidate. No reader or writer looks at a file
extension (`ProvBundle.plot(filename)` takes its image format from one). `ProvFormatNotDetected` is raised when no candidate yields a non-empty
document, with the rejecting reader's error as the cause when the content names a format.
Measured on `main`: PROV-JSON, PROV-JSONLD, Turtle, N-Triples and TriG content are each
detected; RDF/XML content is not, since the `rdf` candidate parses with its default `trig`.
The PROV-JSON reader raises on a PROV-JSONLD document (`'@context' is not a recognised
PROV-N record-type keyword`), and the PROV-JSONLD reader raises on a PROV-JSON one.

ProvToolbox's `InteropFramework` (local checkout, 2026-10-16) maps `json`, `provn`,
`jsonld`, `provx` and `xml` for input and output, and `dot`, `gv`, `jpeg`, `jpg`, `png`,
`svg`, `pdf` and `mmd` for output; `pn`, `asn`, `ttl`, `trig` and `rdf` are commented out,
since it dropped RDF.

### 2.5 Pygments

The test environment has Pygments 2.21.0; the `pygments` extra pins `>=2.13`.
`get_lexer_by_name("provn")` returns `prov.pygments.ProvNLexer` through the entry point,
with aliases `provn` and `prov-n`. Pygments ships `Terminal` (16 ANSI colours, options `bg`
light or dark, `colorscheme`, `linenos`), `Terminal256` and `TerminalTrueColor` formatters.
Pygments has lexers named `turtle`, `json`, `jsonld` (also `json-ld`, a JSON lexer that
colours `@context`, `@id` and `@type` as keywords), `xml` and `graphviz` (also `dot`), and
none for TriG, N-Triples or N-Quads; `get_lexer_by_name("nt")` returns NestedText, so a lookup by
`rdf_format` name would colour N-Triples wrongly. `get_lexer_by_name()` defaults to
`stripnl=True, ensurenl=True`, which adds a trailing newline to PROV-N and JSON output and
collapses rdflib's two trailing newlines on Turtle to one. Pygments reads neither `NO_COLOR` nor `TERM`. `prov.pygments` imports nothing from
`prov` (CLAUDE.md, architecture page), and `test_pygments.py` runs a no-Pygments subprocess
case.

## 3. Writer and reader options (#667, C2, C3, C4)

Before: `prov-convert` calls each writer and reader with its defaults, so a pipeline that
compares PROV-N line by line, or against files 3.2.x wrote, has no way back to the one-line
shape, and `strict`, `force_types`, `rdf_format`, `context` and `indent` are out of reach.

After: two repeatable flags carry any declared option to the writer or the reader.

```
-w NAME=VALUE, --writer-option NAME=VALUE
-r NAME=VALUE, --reader-option NAME=VALUE
```

The rule. Each serializer declares `serialize_options: ClassVar[frozenset[str]]` beside
`deserialize_options`, a closed set of the keywords its `serialize()` takes and the command
line may name. The sets are `provn` {`strict`, `width`}, `rdf` {`rdf_format`}, `xml`
{`force_types`}, `json` {`indent`, `sort_keys`, `ensure_ascii`} and `jsonld` {`context`,
`indent`, `sort_keys`, `ensure_ascii`} (C4). `ProvJSONLDSerializer.serialize()` gains
`context: str = "url"` as a named parameter in place of the `pop` from `**args`, so every
declared name is a parameter of its `serialize()` or a `json.dump` keyword. The remaining `json.dump` and rdflib keywords
stay reachable from Python through `**args` and are not on the command line. A Graphviz
output format takes `prov_to_dot`'s five keywords, held in the CLI's one Graphviz entry
since no serializer owns them. A value is split at the first `=` and typed by one fixed
rule: `none` (any case) is `None`, `true` and `false` (any case) are booleans, an optionally signed
run of digits is an integer, anything else is the string as given (C3). The CLI checks each name itself,
since `serialize()` and `deserialize()` swallow an undeclared keyword (2.3). A name the
chosen format does not declare is an error at exit 2, in `prov.read()`'s sentence:

```
prov-convert: error: the 'provn' writer accepts no option 'wdith'; it accepts: strict, width
```

and `reader` in place of `writer` for `-r`. A flag without `=` is a usage error from
argparse. With `-i auto` (section 5), the CLI checks a `-r` name against the union of every
reader's command-line set, and `prov.read()` then gives each candidate the names it
declares, as it does today. For `-r` and `-R` the CLI subtracts from each reader's
`deserialize_options` the names a command-line string cannot carry, the five JSON reader
callables (`object_hook`, `object_pairs_hook`, `parse_constant`, `parse_float`,
`parse_int`) and the RDF reader's `relation_mapper` and `predicate_mapper`. Naming one
prints the same "accepts no option" sentence at exit 2, and `--help` does not list them. So
`-r` reaches `profile` (`provn`) and `rdf_format` (`rdf`), and the JSON, PROV-JSONLD and
XML readers take no command-line option. A string `relation_mapper` would make the RDF
reader misread a document silently at exit 0, because `if pred in relation_mapper` becomes
a substring test, so a value a reader cannot use does not reliably fail inside the reader.
The library is unchanged.

`prov-compare` takes `-r NAME=VALUE` for file 1 and `-R NAME=VALUE` for file 2,
repeatable, mirroring its `-f`/`-F` pair (C16); the `NAME=VALUE` parsing, typing and
checking live in one helper in `prov.scripts` that both tools call.

`convert_file()` gains keyword-only `reader_options` and `writer_options` mappings (and
`color`, section 4), keeps its positional signature and its `input_format="json"` default,
and accepts `"auto"` (C15). It drops the `provn` branch and routes PROV-N through
`serialize(format="provn", **writer_options)` like every other registered format; the
Graphviz branch stays. `--help` lists each format's accepted names from the declared sets, so
a serializer that declares a new option appears on the command line with no CLI change.

What a person sees: `prov-convert -f provn -w width=none doc.json` writes what 3.2.3 wrote;
`-w strict=true` writes the strict profile; `-w indent=2 -f json` indents; `-w
rdf_format=turtle -f rdf` writes Turtle; `-r profile=lenient -i provn` reads leniently; `-w
use_labels=true -f svg` draws labels.

The alternative, one named flag per option, loses because every new option is a CLI edit
and the Graphviz five double the list (C2).

## 4. Colour (#684, C5)

Before: `prov-convert -f provn` writes plain text to a terminal although `prov` ships a
PROV-N lexer since #628.

After: `--color {auto,always,never}`, default `auto`, on `prov-convert` only, since
`prov-compare` writes nothing on success.

The rule. Under `auto` the output is coloured when all of these hold: no output file is
named, standard output is a terminal, `NO_COLOR` is unset or empty, `TERM` is not `dumb`, Pygments
imports, and the output format has a lexer. `always` colours a file or a pipe too, for
`less -R`; `never` writes plain text. One explicit map gives the lexer name, and nothing is ever looked up by a format's own
name (`nt` names Pygments' NestedText lexer, 2.5): `provn` to `provn`, `json` to `json`, `jsonld`
to `jsonld`, `xml` to `xml`, `dot` to `graphviz`; for `rdf` the map keys on the `rdf_format`
writer option, `turtle` to `turtle`, `xml` to `xml`, `json-ld` to `jsonld`, and nothing for
`trig`, `nt` and `nquads`, so the default `-f rdf` is plain unless `-w rdf_format=turtle` is
given (C18). The other Graphviz formats are binary and never coloured.
A format with no lexer writes plain text under `always`, without a message. The formatter
is Pygments' 16-colour `TerminalFormatter` with its defaults, which follows the terminal's
palette and reads on light and dark backgrounds; no style or `bg` flag. `always` without
Pygments is an error at exit 2:

```
prov-convert: error: --color=always needs the optional "pygments" extra; install "prov[pygments]"
```

`main()` decides the boolean from the flag and the environment and passes
`convert_file(color=...)`. When colour is on, `convert_file` serialises to bytes as the plain
path does, decodes them as UTF-8, highlights the text, encodes it and writes the bytes, and
writes the plain bytes when the text holds a carriage return; when off, the path is unchanged. The lexer is fetched
by name through Pygments' registry with `stripnl=False, ensurenl=False`, never imported from
`prov.pygments`, so that module's "imports nothing from prov" rule stands. Colouring is
lossless: with those two options the output with its ANSI sequences stripped equals the
plain output for every lexer in the map (measured on 2.21.0); with the defaults it would
add or drop a trailing newline.

## 5. Format detection (C6)

Before: `-i` and `-f` default to `json`, so `prov-convert in.provn out.xml` fails parsing
PROV-N as JSON, and `prov-convert in.json out.provn` writes JSON into a `.provn` file.

After: both default to `auto`, and `auto` is an accepted spelling of either.

The rule. One table in `prov.scripts` maps a lower-cased extension to a format and, for RDF,
to the `rdf_format` the reader or writer needs:

| Extension | Format | `rdf_format` |
|---|---|---|
| `.json` | `json` | |
| `.provn` | `provn` | |
| `.xml`, `.provx` | `xml` | |
| `.jsonld` | `jsonld` | |
| `.ttl` | `rdf` | `turtle` |
| `.trig` | `rdf` | `trig` |
| `.nt` | `rdf` | `nt` |
| `.nq` | `rdf` | `nquads` |
| `.rdf` | `rdf` | `xml` |

For input, a path with a known extension decides, `.json` included: a PROV-JSONLD file
named `.json` exits 2 with the PROV-JSON reader's error, and the user passes `-i jsonld`
(C17). An unknown extension or standard input falls to `prov.read()`'s content detection,
with standard input buffered into memory first so the detection can rewind. RDF/XML is the
one format content detection cannot find (2.4), so on standard input it needs `-i rdf -r
rdf_format=xml`, and the reference page says so. Extension first because content detection parses the file once per
failed candidate and rdflib's attempt on a large PROV-N file is the slow one. For output, a
named file decides by the same table plus the Graphviz names in `GRAPHVIZ_SUPPORTED_FORMATS`
(`out.svg`, `out.png`, `out.pdf`, `out.dot`); standard output or an unknown extension writes
`json`, so every command that works today without flags writes what it wrote. An
`rdf_format` the table implies is a default that `-r rdf_format=` or `-w rdf_format=`
overrides. An explicit `-i` or `-f` always wins. `main()` owns the table, since it has the paths, and
resolves both formats before the call; `convert_file()` receives a resolved output format
and either a resolved input format or `"auto"`, which it answers with `prov.read()` on the
stream. `prov-compare`'s `-f` and `-F` take the same
default, so `prov-compare a.provn b.xml` works. A failed detection is an error at exit 2
carrying `ProvFormatNotDetected`'s message, followed by its cause when it has one.
The table is CLI-only; the library's `read()` and `serialize(path)` are unchanged
(section 11).

What a person sees that differs from 3.2.3: a flagless output file whose extension names a
non-JSON format now gets that format. Nothing else that worked changes its output.

## 6. The scripts modernised (C7, C10, C11)

Each item names the behaviour after; the behaviour before is in 2.1.

1. `-V` prints `prov-convert 3.3.0` and `prov-compare 3.3.0`, from `prov.__version__`
   (`3.2.3` on `main` until the release stamp).
2. `main(argv=None)` parses `argv`, and `None` means `sys.argv[1:]`; `sys.argv` is never
   modified (C10). Only a Python caller of `main()` notices. Each parser sets
   `prog="prov-convert"` or `prog="prov-compare"`, since argparse otherwise derives it from
   `sys.argv[0]`, which under an in-process call is pytest's.
3. `--help` is a one-line description, the options and an epilog of examples. The banner
   and `USAGE` go.
4. A runtime error prints one line ending in a newline, `prov-convert: error: <message>`,
   written by the tool in the shape of argparse's own error line; a usage error keeps
   argparse's form, the usage line and then that line. `CLIError` keeps its name and drops
   the `E: ` prefix in `convert.py`; `compare.py`'s copy, never raised, goes. Exit codes
   stay 0 and 2 for `prov-convert` and 0, 1 and 2 for `prov-compare`, with 130 added by
   item 6.
5. The template scaffolding goes: `DEBUG`, `TESTRUN`, `PROFILE`, the doctest and cProfile
   block, the module logger, `__date__`, `__updated__`, `__version__` and the empty
   `__all__`. The `__main__` block is `sys.exit(main())`. The module docstring is one
   paragraph.
6. Both tools exit 130 on `KeyboardInterrupt`, silently (C11).
7. The format lists in the help text come from `prov.serializers.Registry`, plus "or a
   Graphviz output format" for `-f`.
8. Format detection (section 5).
9. PROV-N routes through `serialize()` (section 3).

## 11. Out of scope

- `--from` and `--to` in place of `-i` and `-f`, shell completion, `--quiet` and `--verbose`:
  no request, and each is a compatibility surface to keep.
- #629, a structural diff from `prov-compare`: backlog, as ruled 2026-10-28.
- Format detection from a file extension in `prov.read()` and `serialize(path)`: a library
  change nobody has asked for; a backlog candidate, no issue yet.
- rdflib's and `json.dump`'s other keywords on the command line: reachable from Python,
  closed sets on the command line (C4).
- A style or background flag for colour, and a TriG lexer: Pygments has none for TriG, and a
  style flag is a second surface to maintain (C5).
- Man pages in the wheel or the sdist: a wheel has no clean `share/man` path; the release
  assets and Debian's own build serve the consumers (C8).
- `.pn` as a PROV-N extension: ProvToolbox has it commented out (C18).
- `prov.pygments` is unchanged.
- The replies on Debian bugs 1125295 and 1148660, #705, #726, the PyPy 3.12 job, the #494
  roadmap clause and the release docs audit: spec 7 (C1, C9).
